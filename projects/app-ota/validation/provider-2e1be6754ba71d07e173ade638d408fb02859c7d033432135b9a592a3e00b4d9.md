## 背景与接口决策

研发临时固件可能沿用设备当前版本号，需要允许同版本重刷、降级测试及同一成功包重复刷写。

统一复用版本策略入口 `--version-rule force`，不新增独立开关。实现迭代中曾使用独立参数，提交前已移除，最终仅使用版本策略入口。缺省仍为 diff，重复指定策略时以最后一次为准，策略值大小写不敏感，既有 higher/newer 兼容保持。

| 策略 | 升级决策 |
| --- | --- |
| diff | 默认，包版本与当前版本不同则升级，允许降级 |
| higher | 包版本高于当前版本才升级 |
| force | 不比较升级前版本，对包内存在的固件设置升级标志，允许重复成功包继续处理 |

非强制模式遇到未知版本仍沿用保守升级规则；MCU/电机检测为 boot 阶段时仍置位对应升级标志。

## 使用说明

指定升级包强制升级：

```bash
prog_ota /var/run/media/mmcblk0p1/vstrong/ota-update.tar.gz --version-rule force
```

使用默认包路径：

```bash
prog_ota --version-rule force
```

指定解包限速：

```bash
prog_ota /var/run/media/mmcblk0p1/vstrong/ota-update.tar.gz --version-rule force --rate-kib 512
```

默认包路径为 `/var/run/media/mmcblk0p1/vstrong/ota-update.tar.gz`。解包限速范围为 16 到 2048 KiB/s，默认 512 KiB/s。日志 `rule=force` 表明已选择强制策略。

## 执行与安全边界

- `soc`、`mcu`、`wheel_motor` section 缺失时跳过对应固件；wheel_motor 存在时两侧电机均设置升级标志。
- 升级按左右轮电机、MCU、SoC 顺序执行，任一步失败即进入失败处理。设置全部升级标志不代表后续固件一定执行成功。
- 强制模式绕过升级前版本比较和成功包去重拦截，仍生成包签名，沿用既有成功签名保存流程。
- 保留包头、路径与 MD5 校验、进程互斥锁、UART 独占租约、升级后确认及失败处理。
- 当前版本仍查询，用于诊断和 boot/app 阶段识别，不用于强制模式的跳过决策。
- 临时电机固件的 guide.toml 目标版本应与固件实际返回版本一致，以满足现有目标版本确认。
- OTA 可能停止主业务并触发重启。Git 推送不等于设备部署，需确认设备 prog_ota 已包含本次提交。
