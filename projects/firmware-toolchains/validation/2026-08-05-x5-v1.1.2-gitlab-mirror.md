## 长期升级约定

1. 新 SDK 发布时先读取供应商 manifest，核对项目集合、路径、release SHA 和新增/删除项目。
2. 对已有项目同步供应商新增分支和 tags，不 force-push，不移动既有 release tag。
3. 新版本建立独立内部 manifest 分支，不覆盖旧版本固定 SHA。
4. 内部补丁按版本建立独立分支；旧补丁需重新执行适用性检查和语义验证，不直接假定可复用。
5. 每次升级从空目录执行 `repo init`、完整 `repo sync`、SDK 构建、镜像打包和开发板启动验证。
6. GitLab 只保存源码历史、manifest 和可追踪补丁；二进制交付物是否归档到 NAS 由开发者人工决定，不自动执行。

## 风险与回退

- 当前只证明远端 refs 一致且 manifest 可初始化，不证明所有项目已从空目录完整同步或 SDK 可构建。
- 内部 GitLab 使用未加密 HTTP，访问凭据和源码传输缺少 TLS 保护，应迁移到 HTTPS 并轮换曾通过不安全通道使用的凭据。
- 历史扁平镜像尚未删除，可作为迁移期回退来源；删除前必须确认没有 CI、本地 remote 或自动化仍引用旧路径。
- 回退时优先使用供应商 release tag 和固定 manifest SHA，不修改已经发布的历史分支或 tags。
