# A123X Wi-Fi 四线诊断优化实现与验证

日期：2026-10-26。Linux kernel 6.12 / C5 DEVWIRE。用户授权按前轮建议优化，随后要求继续推进。本轮实现诊断与受控对照能力，不声明四线根因已确认或故障已修复。未刷机、未访问设备、未提交或推送。

## 改动与行为

1. common_drivers/arch/arm64/boot/dts/amlogic/c5_f20_devwire-wifi.dtsi：删除会关闭错误快照的mmc_debug_flag继承属性；保留20MHz/1-bit/OOB选择和其他已有改动。
2. common_drivers/drivers/mmc/host/meson-gx-mmc.c：SDIO错误现场输出raw/masked状态、接收/发送/描述符/响应/超时分类、raw FSM、ios/CFG位宽、timing、请求/实际频率、chain/bounce、blocks/blksz及采样/pinmux/时钟寄存器。CMD53与其他命令独立限流，各每5秒最多3组快照；不在IRQ中发送MMC请求。原错误返回、IRQ确认和恢复流程未改。
3. 同一主控新增sdio_cmd53_bounce只读布尔参数，默认false。仅匹配SDIO host的CMD53且请求容量不超过既有bounce buffer时选择bounce；其余继续原选择。选择在DMA映射之前，不修改已映射请求的所有权。eMMC/TF不受该开关影响。开关不能在运行中切换。
4. drivers/mmc/core/sdio.c新增sdio_bus_diag只读参数，默认false。标准SDIO初始化完成时，在已claim host的进程上下文用CMD52读回CCCR_IF、CCCR版本及适用版本的CCCR_SPEED。记录实际模组位宽与ios、timing、请求/实际频率，不匹配则告警；诊断读回失败不改变原初始化返回值。默认不增加CMD52访问；开启时每次标准初始化最多增加3次访问。
5. common_drivers/drivers/gpio/pinctrl/pinctrl-meson.c：group配置首次遇到单脚pinconf错误时记录组名/引脚/错误码并返回错误，不再伪装成功。主控clk-gate/default状态切换增加失败日志，保留原时钟操作顺序。pinconf错误传播属于共享驱动行为变化，仍须实板启动回归。

## 使用与实验顺序

当前配置为built-in（CONFIG_MMC=y、CONFIG_AMLOGIC_MMC_MESON_GX=y）。以下内容是待后续获准上板的参数说明，本轮没有修改bootargs或设备状态。

- 构建包含本次内核和DEVWIRE DTB的新镜像后，错误快照无需额外参数即可生效。只替换DTB不能使新增C代码生效，旧固件不会自动包含本轮改动。
- 位宽读回：内核命令行加入mmc_core.sdio_bus_diag=1。
- A/B实验在两包都保持mmc_core.sdio_bus_diag=1、同四线/同频率/同IRQ，A为amlogic_mmc.sdio_cmd53_bounce=0，B仅改成amlogic_mmc.sdio_cmd53_bounce=1。若以后改成模块，则分别在加载对应mmc_core/amlogic-mmc模块时传同名参数；本轮只验证built-in配置。
- 参数只读，不能通过写/sys/module下参数临时切换；已启动设备可只读检查/sys/module/mmc_core/parameters/sdio_bus_diag和/sys/module/amlogic_mmc/parameters/sdio_cmd53_bounce是否与实验一致。
- 四线预期：CCCR_IF低两位=2，ios_width=2，cfg_width=1。若resp=1，则继续CMD响应/采样方向；不能只看CRC文本归因到DAT3。bounce=1表示该次数据请求实际未走描述符链。
- 先验当前一线诊断基线，再在同基线上仅改位宽，核首次F1 CMD53；状态匹配后再做bounce对照。低频/legacy/相位实验继续独立，不混合改动。
