# A123X SDK 基线与原生运行方式审查

日期：2026-10-22。范围：RC1 工作区当前本地增量、integration 构建与检查工具，以及 Wi-Fi / Camera / Display 的配置、构建、安装和运行入口。方式：只读审查；仅 /tmp 产生报告与隔离探针，没有修改工程、构建完整固件、刷机或提交。

本报告依据当前供应商源码、默认配置和项目接入约定判断偏离；没有把未取得的厂商正式规范当作依据。结论为 needs-fix，表示本地增量仍有整改项，不代表 SDK 本身不合格，也不表示已完成全部供应商代码的逐行审计。

## 问题地图

### R1 / P1：原厂 CB400 默认目标已被复合定制覆盖

证据：release-tool/env/platform/defconfig/A123X_CB400_NonSip_LP5X_8GB_SPI-Nor_16MB_eMMC_8GB_defconfig:11-39。

同名原厂目标现在启用 SSH、DEBUG、网络 ADB、开发免认证/LAN 模式、W1U Wi-Fi、Ethernet，改用 peripherals DTB、config_800W.json，以及独立 recovery DTB 与 OTA 硬件标识。单项功能可能具有各自授权和必要性；问题在于选择原厂名称已经无法得到原厂默认行为，外围适配、开发调试、更新策略相互绑定，影响基线对比与回归定位。

新鲜检查：integration/scripts/a123x-board-projects.sh --sdk-root <RC1> --dry-run 返回 1，准确指出该 defconfig 的 baseline changed。不是 DTS 标签不可读导致。

建议：保留供应商默认目标，增加明确命名的 CB400 外围/开发 profile，将已授权的功能选择放入该 profile；检查器同时维护供应商基线与定制 profile 身份。不要仅更新旧 baseline hash 来消除失败。新增 profile 前核对项目使用者与构建入口，避免把已有合法开发用途撤销。

### R2 / P1：DHD 手动查找节点忽略 status=disabled

证据：common_drivers/drivers/wireless/wifi/bcmdhd/vendor/bcmdhd/dhd_gpio.c:227-234；patches/0003-a123x-sdio-rescan-and-oob.patch:46-83；内核 drivers/of/base.c:948-963。

生效配置 CONFIG_BCMDHD_DTS=y 使用 of_find_compatible_node，全树按 compatible 查找；该 API 不筛选节点 availability。本地补丁检查 GPIO 错误并释放节点引用，但没有增加 of_device_is_available。触发条件是 DT 中保留具有有效 GPIO 的 android,bcmdhd_wlan 节点并设为 disabled，同时显式加载 DHD。此时仍可能请求 GPIO 并继续上电，违反 DT 禁用语义。当前 DEVWIRE 节点是活动候选，因此这不是对现有日志故障原因的新断言。

建议：在内核侧验证节点 availability，拒绝禁用节点并正确释放引用；如可能存在多匹配节点，明确只选择可用且唯一的目标。补充 missing / disabled / available 三类负正例。保持 vendor 原件不可变，通过受校验的补丁实现。不要恢复用户态 DT 标签门禁，也不要关闭 SDK 节点优化。

### R3 / P1：构建期间源码变化未被通过判定拒绝

证据：integration/tools/codex_assets/a123x_build.py:80-82,111,140-156；a123x_build_state.py:25-52。

工具仅在阶段前后比较 rules_fingerprint；其范围主要是构建规则、工具和配置，不包括 DHD / Sensor / Display / loader 实现或 DTS。源码记录 source-before.json 与 source-after.json 分别保存，但没有比较源码输入变化后使本次构建失败。存在源码构建期间被修改、最终仍标记 pass 的路径。锁为合作式互斥，不覆盖不遵守它的其他修改入口。

新鲜隔离复现：/tmp/a123x-sdk-review-probes.py 在已有构建测试 fixture 中令构建前后 tracked_diff_sha256 不同，底层构建及镜像检查均为明确标识的 synthetic，最终 wrapper 仍返回 status=pass, exit_code=0。另一探针修改临时 loader C 内容，rules_fingerprint 不变。探针没有运行 SDK 构建或访问设备。

建议：冻结并核对真正消费的源码、配置、DTS、补丁和固件输入；按原生 SDK 行为排除已确认的生成文件，避免把安装阶段合法重写当输入漂移。构建完成后再次校验，变化则不发布 pass 制品；完整构建与输入编辑遵守同一锁。

### R4 / P1（追溯）：关键新增源码不在有效源码记录中

证据：integration/tools/codex_assets/a123x_upgrade.py:182-201。effective_source 仅记录 HEAD tree、git diff --binary HEAD、tracked_status，并明确返回 untracked_checked=false、ignored_checked=false。

本次增量中，F20 defconfig/DTSI、产品加载器、Sensor、显示组件及 DHD 包存在未跟踪关键文件。其内容变化不会进入 tracked_diff_sha256，因此现有 source-before/after 不能完整绑定实际构建输入。这是记录范围缺口；工具已明确暴露未检查标志，不能说它伪造了完整追溯。

建议：对新增且实际消费的源码、构建输入、固件及补丁建立内容清单/hash，拒绝未解释的输入缺项。保持本地增量可审查，不因本审查自动提交，也不把整个 ignored 输出目录纳入源码。R3 解决变化判定，R4 解决输入集合，两者应一起收口。

## 优化项与未完成接入

1. Camera IQ 的私有桥接应收口。linux/mbp/sample/pipeline_demo/sensor_guard.c:30-63 在 sample 中额外约定 sc5336p_iq_static_v1 / dynamic_v1、固定插件路径和实验选择。现有拒绝无 IQ 与防止实验 donor 静默冒充的行为应保留；最终应以真实厂商 IQ 和既有 Sensor calibration callback 为中心，将器件专属 provider 适配集中到 Sensor 组件，减少 sample 的私有协议责任。这是可维护性优化，尚不能宣称违反正式 ABI。
2. Camera 板级路由仍未闭环。vi.c:62-64 固定 SC5336P combo devno=0，guard 限制单 sensor0；不能仅凭 sensor ID、RAW 工具或实验 RX 成功认定 CSI_CD/其他接收器已接入原生 pipeline。应核对物理接口、receiver、MCLK、I2C、VI/ISP 映射并沿 SDK 配置表达。真实 IQ 与正式采集 HIL 仍独立验收；不应为使测试变绿而绕过 guard。
3. Display 当前是组件与诊断阶段。NV3006A 位于 aml_spi_display，保留 SDK 显示组件责任合理；原有 ST7789 运行链路不自动适用于该屏。Quad 控制器/引脚、传输协议、panel 初始化和帧更新应形成正式入口与资源 owner，再验证实屏；在这之前保留显式诊断、无默认主屏接管。未验证属于能力缺口，不直接定性为代码违规。
4. 基线/开发/外围与实验状态应分开表达。现有项目状态与文件安装可作为候选证据，但三外围应分别列出 compiled / installed / loaded / functional / low-power 等可观察结果。缺 HIL 不倒推出源码违规，Host 测试通过也不升级为产品放行。

## 应保留的适配与排除的误报

- drivers/of/base.c 没有本地改动；CONFIG_AMLOGIC_DTB_NODE_OPT=y 是 SDK 原有行为，当前 DEVWIRE 源码 defconfig 与生成 .config 均为 y。不得为新增用户态标签读取关闭它。
- modules_sequence_list 的变化有原生生成原因：release-tool/env/mk/Makefile.kernel:163 按 AML_KERNEL_MODULE_SEQUENCE_LIST 复制配置选定的表。不能仅凭大 diff 判定模块加载被手工破坏；后续审查应看被选中源表和实际 rootfs，而非回退生成目标。
- W1U Makefile / Makefile_PC 排除 %.mod.c 防止生成导出表进入驱动，是有明确增量构建理由的适配；print_version.c 删除与原生 clean 规则相符，不直接当源码丢失。
- DHD 置于外置包，依赖原生 cfg80211 加载并唯一拥有 REG_ON；禁用旧 Wi-Fi/BT owner、显式固件路径与 fail-closed GPIO 检查应保留。
- SC5336P 只有一个 Sensor 库构建安装责任；诊断与实验入口独立选择，应保留。
- OTA 硬件兼容检查、独立 recovery DTB、显式容量都是可解释的可选扩展。应从原厂默认 profile 迁出定制选择，不因新增而全盘撤销。
- 调试 SSH/网络 ADB 在其他工作中已有明确需求；本审查不撤销该授权，也不把授权开发模式本身判为未授权行为。这里审查的是 profile 范围和基线可复现性。
