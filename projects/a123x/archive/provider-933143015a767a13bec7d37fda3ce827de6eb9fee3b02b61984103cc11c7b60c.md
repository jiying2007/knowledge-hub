# CB400 DEVWIRE AP6303 WiFi排查进展与4SW1启动拨码说明

记录日期：2026-10-22，Asia/Hong_Kong。
主题：debug-notes；来源为本轮用户反馈、两轮启动日志、当前SDK只读核查及CB400原理图。本文仅整理可复用结论，不含完整串口日志、芯片标识、MAC、凭据或固件二进制。结论按证据层级划分，WiFi故障尚未闭环。

## 现场条件与对照边界

- 用户说明：开发板版本固件搭配另一颗插在PCIe/M.2位置的55S2无线模组，WiFi可正常工作；DEVWIRE版本搭配SDIO AP6303飞线不工作。二者模组、接口方案及固件均不同，不能把55S2正常视为AP6303或SDIO通路验证通过；连接器位置也不能单独证明其内部实际总线。
- 用户确认：原SDIO模组已拆除，AP6303的WIFI_EN飞线焊在原模组9U1焊盘；3.3V、1.8V、共地及断电后的CLK/CMD/WIFI_EN通断已检查。用户曾用示波器在开发板端观察到WIFI_EN低、CMD高、CLK低，上电期间未见变化。
- 尚未获得同一次新固件启动的波形、准确测点照片、PCB版次或完整板内AO17到9U1的通断证据。静态飞线导通不等于SoC到焊盘通路或动态信号正常。

## 已定位的失败阶段

Linux启动、eMMC根文件系统挂载和SDIO host fe088000注册完成。DHD取得REG_ON全局GPIO659和HOST_WAKE GPIO655，上电等待后触发SDIO重扫；CMD5参数0连续超时，随后mmc1报告不可移除卡初始化失败，DHD重试耗尽返回-19/ENODEV。

这说明失败位于SDIO初始枚举，尚未进入可验证的固件下载、扫描、关联或DHCP阶段。bcmdhd.ko文件已执行初始化，insmod的No such device不是文件不存在。failed to power up是等待卡就绪失败的汇总消息，不能单独证明供电故障。

此前板端bcmdhd.ko SHA256为25de9c8156865de15faf1127c605a8d1f89fcdd2e1db6dc2742c2391f41d9790，与当时本机目标rootfs一致。新增诊断后用户提供了内核构建时间20:31:11、DHD构建时间20:32:18的启动日志；REG_ON_DIAG已生效，但未提供这次板端ko哈希，不能把它等同于先前隔离构建候选的字节身份。

## GPIO读回诊断及新运行证据

受管0007-a123x-reg-on-readback-diagnostics.patch只在BCMDHD_A123X下采样：设置前、设置后、原有200ms等待结束后的SDIO重扫前。记录gpio、requested、set_rc、dir、raw；不直接访问物理寄存器，不增加等待，不改变输出、错误、重试或释放策略。dir=0输出、1输入、负数表示读取失败；raw为控制器原始输入采样，不是输出锁存或实际焊盘电压证明。before-set的set_rc=-115表示尚未执行，不是控制失败。

新日志首次过程：

| 内核时间/秒 | 阶段 | 证据 |
|---|---|---|
| 2.129 | before-set | dir=1 raw=1 |
| 2.131 | after-set，高 | set_rc=0 dir=0 raw=1 |
| 2.337 | before-sdio-rescan | dir=0 raw=1 |
| 2.345至2.348 | CMD5 | timeout |
| 4.380 | after-set，低 | set_rc=0 dir=0 raw=0 |

后续重试均出现拉高读回1、拉低读回0、重扫前仍为1的模式。由此排除DHD未调用拉高和设置API直接报错；没有证明实际9U1焊盘高电平、mux/输出锁存正常或采样间无瞬态。最终失败会拉低并释放GPIO，启动后测到低不能反推上电窗口。

## PCIe与SDIO共存核查

本机当前DEVWIRE DHD实际编译命令含BCMSDIO、BCMLXSDMMC、BCMDHD_A123X，不含BCMPCIE/PCIE_FULL_DONGLE。继承的CB400 DTS将pcie和pcie_phy设为disabled，PCIe reset配置GPIOF_5，DHD REG_ON配置GPIOAO_17。未启用BCMPCIE时PCIe加载函数为空实现，SDIO初始化报错后直接退出，并非失败后转PCIe。

当前未发现双总线同时驱动WiFi的证据。硬件共电源、选件和实际路由仍须实测；不能将源码配置等同于所有运行固件和所有接口组合。

## 4SW1的准确作用

来源：downloads/CB400/00-A123X2_CB400_V1.0_R0.6_Release_20260924/01_SCH/A123X_CB400_DEV_BOARD_LPDDR5_6L_HDI_V10_R07_SCH_20260920-BOM.pdf，PDF第9页/图纸Sheet8，POWER ON CONFIG与POC Table1/2。本轮已读取文本并查看该页图形连接。

原理图PDF SHA256：5138cdd4d537baf61702e2a73f20ca71467943d9c680adf0f1dc5334f01d46cf。

4SW1是两位启动配置拨码，不是WiFi PCIe/SDIO接口选择开关。

| 拨码 | 控制信号 | 连接与作用 |
|---|---|---|
| 1 | POC4 / GPIOB_4 | 经6R26关联EMMC_D4；ON闭合到GND，选择低 |
| 2 | POC7 / GPIOB_7 | 经6R29关联EMMC_D7；ON闭合到GND，选择低 |

OFF断开接地，按图纸默认上拉为1，实际装配与采样仍需确认。完整启动选择由POC5、POC7、POC4共同决定，4SW1不直接控制POC5，POC5有独立配置/按键电路。

仅在POC5实际为1的条件下：

| 拨码1/POC4 | 拨码2/POC7 | POC5/7/4 | 图纸启动优先级 |
|---|---|---|---|
| ON | OFF | 110 | eMMC → SD → USB |
| ON | ON | 100 | SPI NOR → SD → USB |
| OFF | ON | 101 | SPI NAND → SD → USB |
| OFF | OFF | 111 | SPI NAND → SD → USB |

这里的SD是启动介质，不是AP6303的SDIO接口选择。ON表示开关闭合拉低，不表示逻辑1。调整前记录原位，断电操作，再重新上电确认；不凭照片左右推断ON方向。当前已能从eMMC启动至Linux，尚无4SW1直接导致CMD5超时的证据。

更正说明：用户最初泛指两个开关时曾解释13SW6电源滑动开关和10SW1麦克风静音开关；用户补充位号4SW1后，该泛指解释不适用于本次所问器件。后续以4SW1启动配置说明为准。
