# DEVWIRE Wi-Fi选装电阻NC状态与CMD5超时排查补充

记录日期：2026-10-23。

来源：用户在本次侧会话报告“9R14~9R20，9R83，9R84都是NC”；同一会话解释NC/0R含义并要求更新归档。信号映射已与当前项目CB400-DEVWIRE.md接线表核对。启动日志依据为用户此前提供的受限串口片段，本文仅提取结论，不保存原始日志或设备标识。

## 新增事实与证据边界

- 用户报告上述电阻为NC，按当前讨论理解为未装状态。尚未独立检查实物、装配BOM或万用表通断；若用户指的是原理图标注，则还需确认实板是否确实未装。
- 原理图的NC/0R表示可选装配：不装时该电阻位置不导通，装0Ω时接通。原理图标注本身不能证明实际装配。
- 飞线指导采用9U1空模组焊盘到AP6303BH转接板，但实际焊点位于电阻哪一侧、有无跨接旁路尚未实测确认。

## 对现有接线的影响

| 电阻 | 路径 | 未装且无旁路、飞线取自9U1侧时的影响 |
| --- | --- | --- |
| 9R15 | GPIOX0到9U1.21，SDIO D0 | 数据线断开 |
| 9R16 | GPIOX1到9U1.22，SDIO D1 | 数据线断开 |
| 9R17 | GPIOX2到9U1.20，SDIO D2 | 数据线断开 |
| 9R18 | GPIOX3到9U1.19，SDIO D3 | 数据线断开 |
| 9R19 | GPIOX4经9R41到9U1.18，SDIO CLK | 时钟通路断开，另须核9R41 |
| 9R20 | GPIOX5到9U1.17，SDIO CMD | 命令及响应通路断开 |
| 9R83 | 9U1.16 HOST_WAKE到GPIOAO13 | OOB唤醒信号通路断开 |
| 9R84 | GPIOAO17到9U1.15 WIFI_EN | SoC输出不能经该路径到达转接板EN |

9R14属于原模组外部32k时钟选装支路，不与上述八处一并建议补装。转接板已有标注32.768的器件，应先确认本地LPO有效；不能在未确认来源时并联两个时钟输出。

## 与启动日志的关联

- 新EN反相行为已在设备日志中出现：active_low=1；逻辑开启时output=0、dir=0、raw=0，关闭时output=1、raw=1。
- 这些读回仅证明SoC控制器端状态。若9R84未装且无旁路，SoC读回正常也不证明转接板输入或模组内部EN到位。
- 随后CMD5（参数0）反复超时，最终模块初始化返回ENODEV；未进入固件下载和联网阶段。
- 在上述线路断开的条件成立时，EN、CLK或CMD断路足以解释无法枚举。这是优先核查的物理路径问题，尚未通过接通后的复测确认根因闭环，不能宣称硬件已修复。
- 9R83缺失影响HOST_WAKE，但不能单独归因为CMD5无响应；CMD5阶段优先查供电、EN、CLK、CMD，之后完整核对DAT0至DAT3。

## 下一步

1. 断电核实电阻实装、飞线真实落点及跨接情况，逐线测SoC侧到转接板接点的通断。
2. 若沿用9U1侧取点且确实无旁路，按板级方案接通9R15至9R20、9R83、9R84，通常采用0Ω电阻；另核9R41及原无线/M.2支路隔离。本文不是已执行补焊的记录。
3. 保留9R14待确认，核转接板3.3V/1.8V、电源稳定性和本地32k。
4. 重新启动并在使能窗口实测AO17低、转接板反相后的内部WLAN EN高；观察转接板端CLK/CMD及CMD5响应，再验证枚举、固件与联网。
5. 当前没有依据继续翻转软件极性或仅靠增加延时处理断路。
