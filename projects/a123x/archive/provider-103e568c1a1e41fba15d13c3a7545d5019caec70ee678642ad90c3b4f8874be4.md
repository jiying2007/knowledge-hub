## 3. 供电、线缆与首次上电

### 3.1 各输入的区别

| 接口 | 图纸用途 | 操作要求 |
|---|---|---|
| 12CON1，DC座 | 12V DC，板上先降为5V再进入系统/充电路径 | 确认本板DC座极性和适配器规格后使用；CAD pin1=DC12V_P，pin2/3=GND，不能据CAD脚号猜插头机械极性 |
| 12J1，Type-C | 5V输入与USB2数据；CC各有5.1k下拉 | 当前原理图未见支持12V输入的PD控制器；不要将12V送入该Type-C口 |
| 14J1，Micro-USB | CP2102 USB转串口的VBUS/数据 | 用于调试桥；不把串口桥枚举当成SoC已启动或主板已供电 |
| 12CON3，电池 | 单节锂电参考，pin1 VBAT-、pin2 NTC、pin3 VBAT+ | 需要保护与10k NTC要求；只在电池方案/极性核准后接入，不接F20的2S/3S电池 |
| 3CON1 pin4 | 板上调试接口电源输出网络 | 首次外接TTL串口只接GND/TX/RX，不借此给板卡供电 |

规格配件项曾写“12V/1A，typeC”，与原理图5V Type-C/独立12V DC路径不能直接合并解释。若实物另有PD转接板，先取得该转接板的完整规格和接法再使用。多个输入的同时接入、供电优先级及反灌能力未获实测，首次使用选择一个已确认的主供电源。

### 3.2 上电前清单

1. 断开全部电源，核对板卡版本、连接器针1、线缆和模块方向。
2. 核对供电电压/极性，确认没有导电异物或明显电源对地异常；电源对地阻值受芯片/电容影响，不用通用固定阻值判所有电源轨。
3. 暂不连接不明子板、外部电池或飞线负载；保留板上已确认的散热和必要天线/配套模块。
4. 连接一种串口调试路径，先打开主机日志采集，再按批准的电源电流限值上电。
5. 使用可限流实验电源时，限流值由本板正常启动峰值/适配器规格确定。限值太低会反复掉电，不能用任意小电流作为启动验收条件。

### 3.3 首次启动步骤

1. 接好已确认的主电源，观察输入电流、指示与温升；出现反接、异常持续限流、冒烟或快速局部过热时断电查电源，不连续强行重启。
2. 如未自动启动，核对13SW6电源滑动开关的实际ON方向，以及当前固件/充电器是否要求13SW2 ON/OFF键。原图未给可通用于所有固件的按压时长，不套用EVT1“三秒开机”。
3. 观察串口按阶段推进：早期启动/DDR初始化→U-Boot→Linux→根文件系统→应用。某阶段无日志不等于该阶段一定未运行，需结合波特率和静默配置判断。
4. 先观察原有固件，不立即升级；记录DDR/存储/内核/设备树及应用身份。
5. 完成第5节只读检查后，再逐个接入模块并验证。修改线缆/子板前正常关机并断开全部可能供电，包括USB反向供电来源。

### 3.4 关机与断电

先停止录像/录音/存储测试等写入任务，通过当前固件支持的关机流程退出，再断主电源。若`poweroff`只关闭Linux而常供电域仍工作，应根据本板电源结构断开相应电源；不要将串口不再输出等同于整板无电。异常死机需要强制断电时记录原因，重启后检查文件系统/业务数据，避免把强断电影响误归为TF自动格式化。

## 4. 串口调试

### 4.1 推荐路径：Micro-USB/CP2102

将主机接到14J1 Micro-USB。Linux主机可先只读查看：

```bash
rtk lsusb
rtk ls -l /dev/serial/by-id
```

如系统提供`/dev/serial/by-id`，按CP2102设备身份选串口；否则结合插拔事件识别实际`/dev/ttyUSB*`，不要假定永远是ttyUSB0。Windows按设备管理器识别对应COM口，确认USB-UART驱动和线缆支持数据。串口权限按主机管理规范处理，不通过全局放宽设备权限解决。

### 4.2 外接TTL串口：3CON1

图纸p17/Sheet16和PCB端点给出：

| 3CON1 CAD针号 | 板端定义 | 外接串口适配器 |
|---:|---|---|
| 1 | GND | GND |
| 2 | Linux_TX，SoC F0，UART_B_AO TX | 适配器RX |
| 3 | Linux_RX，SoC F1，UART_B_AO RX | 适配器TX |
| 4 | VDD33_AO_P | 首次不接 |

板端逻辑为3.3V参考，确认实板电平后使用相应TTL适配器；不接RS-232电平，也不使用5V TX。板载CP2102 TX也接到同一Linux_RX，外部TX与板载桥同时驱动存在冲突风险，使用一种接收/发送路径或按硬件规程隔离。针2/3有串阻后网络名差异，但方向以板端TX/RX定义为准。

### 4.3 波特率、格式与乱码

参考终端格式为8数据位、无奇偶校验、1停止位；不启用未接出的硬件流控。**波特率必须按正在运行的固件和启动阶段确认：**

- 当前SDK的U-Boot `include/configs/amlogic/c5_cb400.h`默认环境写`baudrate=921600`。
- 同板U-Boot DTSI的`stdout-path`写`serial1:115200n8`，存在不同配置来源。
- 因此首次可按匹配固件提供的参数设置；资料不足时在921600和115200分别观察并记录对应阶段。不要为排乱码直接写bootloader环境，更不要执行`saveenv`改变基线。
- 某一阶段正常、随后乱码，优先核对阶段切换后的速率/控制台；全程无字符先查电源、端口、GND/TX方向和桥供电。

本次未测得“全启动链固定921600”或“固定115200”的证据。运行后可读取`/proc/cmdline`确认Linux实际console，U-Boot中只读查看`printenv baudrate`及`printenv bootargs`；读取环境不需要保存或修改它。

## 5. 启动后先做只读检查

以下命令在**板端Linux shell**执行，不是在主机工作区执行；板端通常没有rtk，直接使用固件提供的命令。首次仅观察，不刷写分区、不直接访问寄存器、不改GPIO或挂载选项。

```sh
uname -a
cat /proc/cmdline
cat /proc/meminfo
cat /proc/partitions
cat /proc/mounts
cat /proc/uptime
df -h
dmesg
```

如果固件支持，补充：

```sh
tr '\000' '\n' < /proc/device-tree/model
tr '\000' '\n' < /proc/device-tree/compatible
ls /sys/bus/mmc/devices
ls /sys/class/net
ip link
ip addr
ps
```

某个命令/路径不存在，仅说明工具裁剪或系统布局不同，记录原始错误再按本固件接口排查。不能因`/proc/meminfo`可用内存小于8GB直接认定DDR容量错误，需同时看bootloader训练/识别、保留内存/CMA和设备树。

每次保存启动日志时去掉口令、令牌、Wi-Fi密码和可识别个人信息；MAC/序列号按项目脱敏规则记录。原始日志在受控证据存储保留，长期知识归档仅存必要摘要与hash。

## 6. SDK获取、构建与制品使用

### 6.1 冻结实际板型

本手册的原厂CB400构建目标为：

```text
A123X_CB400_NonSip_LP5X_8GB_SPI-Nor_16MB_eMMC_8GB
```

它关联`c5_cb400`、`meson-c5-cb400.dts`和`c5_a123x_cb400.dtb`。仓库还可能有Fast/BR/NOR等变体，不能仅看CB400字符串选包。F20_DEVWIRE/EVT1配置不等于该目标；LP4X参考也不允许复用本目标宣称已适配。

首次获取源码遵循SDK快速开始（来源内引用：`../../../integration/docs/quick-start.md`；尚未映射为 Hub 链接），复现版本遵循固定源码入口（来源内引用：`../../../integration/docs/fixed-source.md`；尚未映射为 Hub 链接）。已有dirty工作区不要直接同步、重打补丁或清理；先记录实际变更及源码身份。

### 6.2 主机准备与只读构建计划

主机依赖和工具链以构建手册（来源内引用：`../../../integration/docs/build-cb400-rc1.md`；尚未映射为 Hub 链接）为准；doctor检查环境，不安装依赖。下列为主机命令，替换可信绝对路径，证据输出必须是新的SDK外目录：

```bash
export A123X_INTEGRATION=/absolute/path/to/a123x/integration
export A123X_SDK_WORKSPACE=/absolute/path/to/a123x-sdk
export A123X_EVIDENCE=/absolute/path/to/evidence/new-cb400-build

rtk bash "$A123X_INTEGRATION/scripts/a123x-doctor.sh" \
  --workspace "$A123X_SDK_WORKSPACE"

rtk bash "$A123X_INTEGRATION/scripts/a123x-build.sh" \
  --workspace "$A123X_SDK_WORKSPACE" \
  --output-dir "$A123X_EVIDENCE" \
  --board A123X_CB400_NonSip_LP5X_8GB_SPI-Nor_16MB_eMMC_8GB \
  --dry-run
```

先查看计划中的目标、是否需清理共享状态和现有制品保存策略。`--dry-run`不调用`make -n`，不建立构建输出；供应商Make规则可能让`make -n`也执行命令，不将它作为只读替代。

### 6.3 正式构建

确认源工作区和计划后：

```bash
rtk bash "$A123X_INTEGRATION/scripts/a123x-build.sh" \
  --workspace "$A123X_SDK_WORKSPACE" \
  --output-dir "$A123X_EVIDENCE" \
  --board A123X_CB400_NonSip_LP5X_8GB_SPI-Nor_16MB_eMMC_8GB
```

该命令会编译，并在板型切换/状态未知时按入口规则保存白名单制品、清理共享生成状态和重新配置；它不是无副作用检查。单SDK工作区不并发构建多个板型，不混用未遵守锁的原生make。必要时用独立工作区并发。

首次新工作区的供应商补丁仅按构建手册执行一次；已有续编跳过。失败时保留日志和真实退出码，不通过删除输出、手造stamp或再次repo sync掩盖问题。

### 6.4 检查结果和交付制品

查看本次`build.json`的入口退出码、真实`build_exit_code`、运行收据及`artifacts.json`。不能仅凭命令最后输出或镜像文件存在断言成功；失败后遗留的旧镜像也不能交付为新构建。

SDK常见镜像目录为：

```text
output/A123X_CB400_NonSip_LP5X_8GB_SPI-Nor_16MB_eMMC_8GB/images/
```

优先交接本次证据目录保存的`firmware/`，避免后续切板构建覆盖工作目录。典型白名单文件：

| 文件 | 用途 | 额外核验 |
|---|---|---|
| aml_upgrade_package.img | 完整烧录包 | 匹配板型、存储/分区、签名与工具，不等于OTA包 |
| software.swu | SWUpdate升级包 | 核升级handler/兼容条件、写入分区和保数据/恢复语义 |
| boot.img | 启动镜像 | 与其余组件版本配套，不单凭名称决定写入位置 |
| rootfs.ext4 | 根文件系统 | 离线只读完整性检查与分区容量 |
| u-boot.bin.signed | 已签名bootloader制品 | 签名模式/设备适用性，不盲目替换启动链 |

逐文件记录SHA-256。`images/`中可能含供应商测试签名私钥，按既有构建规程只分发白名单文件，不整目录复制。源版本、dirty、manifest、工具版本、构建退出码、镜像完整性和板端结果分别记录。历史主机构建成功只证明对应那次构建，不替代本次镜像或实板验证。

## 7. 下载、升级与恢复

### 7.1 执行前必须具备的信息

现有资料有POC/Update/USB恢复线路，但没有完成实板验证的通用烧录步骤。因此本手册不规定某个工具按钮、固定USB VID/PID、短接点或“按住Update几秒”的动作。

实际执行前由板端负责人确认：

1. 实板型号、装配、DDR/启动存储与镜像目标一致，记录原固件及可恢复身份。
2. 本次镜像hash、构建收据、签名/密钥模式适用；目标存储和擦写范围明确。
3. 烧录工具及版本、主机驱动、数据线、正确下载口、进入下载条件和板卡供电顺序已实测。
4. 擦除全盘/bootloader/用户分区是否允许，业务数据和设备凭据如何保留/备份已明确。
5. 有失败退出和恢复方案；不能恢复时停在准备阶段，不凭参考图试短接。

### 7.2 启动选择的资料解释

原理图p9/Sheet8的POC2决定USB下载端：1对应USB20_B，0对应USB30_A。POC5/7/4组合110对应eMMC→SD→USB的优先级；其他组合可选择SD、USB、SPI NOR/NAND。

这些是原理图表格信息，**不是实板拨码位置指令**。需要确认贴装电阻、默认上下拉、按键对采样节点的影响和复位采样时刻。GPIOB组同时承担eMMC/SPINF，改变其负载或外接设备可能改变启动选择或破坏存储通信。

### 7.3 正确的烧录记录顺序

按批准规程进入下载→主机识别正确设备→核对镜像和目标→执行→保存工具返回及结果→重新启动→分别验证bootloader、Linux、根文件系统与外设。工具报告成功不替代启动验证；Linux启动也不替代OTA/断电恢复和回滚。

Type-C 12J1的USB2路径与14J1 CP2102串口桥完全不同；看到串口COM口不表示SoC进入下载。USB3 Type-A与PCIe又存在PHY选装复用，不能凭接口外形判断当前下载通路。

### 7.4 按键速查

| 图纸位号 | 用途 | 注意事项 |
|---|---|---|
| 13SW1 | Doorbell | 业务/唤醒事件由当前固件定义 |
| 13SW2 | ON/OFF，与充电器及检测关联 | 按压时长与ship行为依当前芯片/固件规程 |
| 13SW3 | RESET_N复位 | 不等于恢复出厂或擦除数据，具体行为由软件决定 |
| 13SW5 | Update，关联Button_REC_RESET | 下载触发条件必须按本板批准流程 |
| 13SW6 | 电源滑动开关 | 依据丝印和实物状态确认，不根据照片左右猜ON/OFF |
| 13K1..K4 | ADC Update/VOL-/VOL+/OK | 图示约0/0.25/0.47/0.68V，属于ADC梯形网络，不是4个独立GPIO |
| 13K5 | Tamper | 开发板自锁结构，恢复释放状态后再判断防拆事件 |

## 9. 外设使用步骤

### 9.1 TF/eMMC/USB存储

先看`dmesg`、`/proc/partitions`和`/proc/mounts`识别设备及挂载点；有`lsblk`时可辅助查看，不能假定mmcblk0一定是TF。TF使用C0..6及C7电源，设备树须匹配插卡有效极性和1.8/3.3V切换。

读写测试只对经确认可用的测试文件/目录执行，明确容量/覆盖范围，不对整设备运行`dd`、`mkfs`或分区操作。拔卡前停止相关业务并按当前固件卸载流程处理。挂载失败先保留日志，不立即格式化；确认是否文件系统、供电/触点、卡检测或IO电压问题。

USB外设可在板端用`lsusb`（如固件具备）和`dmesg`观察。USB3/PCIe共享PHY，未核装配时不将“只枚举USB2”直接定为软件故障。

### 9.2 Wi-Fi/BT

先识别实际模组及0R选装。资料对W1U、W155S2、W1D revC的描述不同；驱动/固件/NVRAM必须与实装一致。检查电源、32.768k时钟、REG_ON、SDIO和唤醒极性后，再检查网络服务。

板端只读观察按固件可用命令选择：

```sh
ls /sys/class/net
ip link
ip addr
cat /proc/net/wireless
```

有`iw`/`wpa_cli`时，使用实际接口与控制目录读`iw dev`、`wpa_cli status`；默认控制目录不匹配时命令失败不代表射频失效。连接AP使用该固件的配置入口，凭据不写进本手册、Git或日志。

依次验收：SDIO识别→固件加载→无线接口→关联→IP→目标服务→断线恢复→BT并发→低功耗唤醒。关联成功不等于获得IP，DHCP成功也不等于云服务可用。BT HCI依赖X6..9/UART_E及其RTS/CTS，不能只看到蓝牙芯片就认定HCI可用。

### 9.3 相机与IR-CUT/补光

断电接入匹配模组，按“电源和对端针序→复位/PWDN→MCLK→I2C器件ID→CSI原始数据→ISP/IQ→编码/业务画面”验证。相机A用AO共享I2C；B端P域控制存在选装，不能照搬A端配置。

如系统采用V4L2且有工具，可用`v4l2-ctl --list-devices`查看；设备未出现时也需确认是否使用厂商媒体API，不假设所有链路都暴露标准video节点。应用命令、Sensor驱动和IQ选择以当前SDK/模组示例为准，不把其他平台的演示二进制复制运行。

相机高速差分不能当普通GPIO飞长线；转接板必须确认P/N、lane/clock、电压和地。IR-CUT与补光由驱动电路带负载，不能让SoC脚直接驱动线圈或大功率LED。I2C读到ID只证明控制链部分成立，不代表出图/帧率/画质通过。

### 9.4 音频

核实装麦数/型号和PDM路由；SED方案使用PDM，不能用AMIC直接替代。板上两麦参考与外接P域PDM扩展是不同路径，扩展电阻未装时不会自动接通。

如固件使用ALSA并提供工具，可执行`arecord -l`、`aplay -l`及`amixer contents`只读发现。录放测试随后根据实际声卡、支持格式/采样率/通道和产品音量策略进行，不套固定card号或最大音量。缺ALSA工具时查厂商音频API/应用入口。

先单独录音验证各物理麦位置与声道，再验证扬声器、静音切换和双向/回声消除。D10参考低=静音、高=使能；SPK-不是地。规格8Ω1W与原图8Ω1.8W存在差异，先确认扬声器BOM及允许增益，观察削顶、pop和温升。

### 9.5 显示与触摸

CB400原接口7CON4是MIPI DSI扩展，包含屏电源、背光/复位、触摸I2C和差分lane，不是F20的双12pin屏接口。先核屏模组供电/时序、lane、分辨率、触摸地址和背光电流。

F20双QSPI屏仍需证明控制器、IO0..3路由、pinmux及协议适配；普通SPI控制器有Quad能力描述，不代表CB400已有四数据线可接。不能为此占用B组启动存储。

### 9.6 RGMII、PCIe、雷达、PIR与IR

- RGMII需匹配PHY子板、1.8V逻辑、MDIO、时钟、复位/中断和P组占用；11CON1不是已装好的RJ45网络口。
- PCIe先核USB3/PCIe 0R选择、时钟/复位/供电和实际lane，再在具备工具的固件中用`lspci`及`dmesg`观察。M.2机械形态不保证所有lane已连接。
- 雷达12CON2的SPI/IRQ/RESET/PWR可能由SoC或Wi-Fi选装控制，确定唯一owner再启动驱动，禁止两端同时驱动。
- PIR资料的RN412/RM412命名不同，先核实物和串行配置。红外接收/433发射的管脚与驱动配置按当前装配核验，不把接收事件等同于测距或悬崖能力。

## 10. 电源域、测量和低功耗

常供电、保持和业务域由AO/STR/PWR_UP等协同控制。观察休眠不能只看Linux是否暂停，须记录实际电源轨、无线/外设状态与唤醒源。

| 测量对象 | 资料线索 | 注意事项 |
|---|---|---|
| DC入口/EXT_5V/VSYS | 12V先降5V，电池/系统电源路径不同 | 输入功耗与分轨功耗分开；适配器效率和USB桥负载要注明 |
| CPU/EE/NPU | PWM动态调压 | 测真实板端电压与负载，不从示例PWM表直接操作 |
| LP5 VDDQ/VDD2H | 专页约0.5V/1.05V，时序页却0.6V/1.1V | 先由DDR/电源owner确认适用值，不用LP4X值验收LP5 |
| P域 | 1.2/1.8V能力，选装决定来源 | 实测当前域，不因扩展头有3.3V供电就接3.3V数据 |
| TEST_N/POR/时钟 | 上电约束、24M/32.768k | 保留信号质量；示波器探头/接地按高速与低压测量规程 |

规格“待机<2mW”缺少本次仪器、边界、无线模式、USB-UART/LED和外设负载条件，不作为已达标指标。测量报告必须给电源电压、仪器/采样、板号/固件、外设状态、时间、平均/峰值及唤醒结果。

休眠测试按单源PIR/SED/无线等逐个验证触发/清除，再做同时触发及循环；先验证恢复通路，避免在唯一串口/供电不可恢复状态下试验。读写GPIO、寄存器、PMIC或系统电源状态属于主动硬件操作，实施时按实际任务授权与恢复流程执行，本次手册编写未执行。

## 11. 常见问题与分层排查

| 现象 | 优先检查 | 下一步证据/处理 |
|---|---|---|
| Micro-USB无COM/ttyUSB | 数据线、主机USB、CP2102/驱动、调试桥VBUS | 主机插拔事件；尚不先怀疑DDR |
| CP2102已枚举但无SoC日志 | 主板电源/滑动开关、实际串口、TX/RX、GND、速率、静默 | 桥枚举不是主板运行证据；换确认的观测路径 |
| 某阶段开始乱码 | 921600/115200配置来源及阶段切换、流控 | 分段保存日志，读运行console，先不改存储环境 |
| DDR前后反复复位 | 输入限流/电压跌落、DDR料号/训练/电源与镜像 | 电源波形、训练日志与板型；不反复盲刷 |
| U-Boot正常、Linux不启动 | 启动介质、内核/DTB/rootfs配套、签名和分区 | 保留bootargs及明确失败阶段，核镜像hash |
| 下载工具找不到设备 | 接的是CP2102而非SoC口、数据线、下载采样/POC、驱动 | 依批准规程核端口/电源/按键，不猜短接点 |
| 镜像文件存在但不能用 | 构建实际退出码、旧制品、板型/DDR/存储/签名 | 查本次build.json与artifacts；不凭时间戳交付 |
| TF不识别或反复掉线 | 触点、供电、卡检测、IO切换、C组复用、文件系统 | 启动/插拔内核日志，先停写和保留介质，不立即格式化 |
| Wi-Fi接口不存在 | 实装模组、SDIO路径、REG_ON反相、32K、固件 | 先物理/枚举再网络配置；查唯一owner |
| Wi-Fi关联但无业务 | IP、路由、DNS、目标服务与认证 | 分阶段记录，不把云端故障当无线芯片故障 |
| Sensor读ID失败 | 对端针序、电源、复位、MCLK、I2C域/上拉/地址 | 不盲扫包含电源器件的总线或随意改地址 |
| 读ID成功但黑屏 | lane/clock、CSI/RAW、格式、ISP/IQ、应用 | 收集链路各级计数/帧摘要；ID成功不是出图通过 |
| 录音无声/通道错 | PDM/AMIC路径、实装、时钟/LR、路由与静音 | 逐物理麦激励，不先改算法 |
| 扬声器无声/pop | D10静音极性、功放电源、SPK差分接线、启动顺序 | 核负载与增益，避免直接满幅大音量 |
| PCIe与USB3不能同时工作 | 共享PHY及0R选装 | 对照装配方案，不能按两个接口均存在开启两驱动 |
| RGMII/PDM/相机B互相影响 | P域pinmux、选装、低电压、电源状态 | 生成资源唯一分配表，按组合重新验收 |
| 不休眠/误唤醒/功耗高 | 常供电负载、USB桥、wake极性/清除、外设反灌 | 先时序/分轨测量，再定位软件保持条件 |
| 构建缺recovery.tar.gz等工具输出 | 工具包是否曾中断、存在目录但内容未完成 | 用共享工具恢复流程（来源内引用：`../../../integration/docs/sdk-tools-recovery.md`；尚未映射为 Hub 链接），不手造完成标记 |

排查先保留原始错误、返回码和版本，再改变一个条件。不要在故障现场同时替换电源、镜像、线缆和模组后只报告“恢复”，否则无法归因。
