# A123X PSI、libgpiod 与按需 ftrace 增量验证

本轮按用户确认，在既有 debugfs/GPIO/pinmux 只读观测基础上补充开发诊断能力。领域结论为源码及本地组件验证完成；不代表完整固件、板端 HIL 或产品发布通过。

实现与决策：
- AML_DEBUG 内默认启用 AML_DEBUG_PSI 与 AML_DEBUG_TRACE。PSI 显式启用统计、不要求额外 psi=1；ftrace 只编译支持，不自动启动采集。保留显式关闭选项。core、perf、KASAN、lockdep 等专项能力不默认增加。
- 新增 AML_TOOLS_PKG_LIBGPIOD，由 AML_DEBUG 选择；使用 SDK 原生包生成器接入 libgpiod 2.2.5。GPIO_CDEV 通过内核通用配置 fixup 启用。rootfs 只安装 gpiodetect、gpioinfo、libgpiod.so.3 及许可证，不安装请求/设置线路工具或 daemon。
- board-diag 增加 GPIO 信息与 clk_summary、regulator_summary、dma_buf/bufinfo。每项 2 秒、32 KiB，缺失或失败不阻断诊断包；PSI 三项统计沿用现有采集入口。
- 开发配置迁移：现有显式关闭的 trace 不会被新的默认值覆盖。本轮备份原活动配置，只启用 trace 后执行原生 make olddefconfig。活动 SDK .config、导出配置、DEVWIRE 输出配置已同步；其他业务启用项保持原值，Kconfig 额外规范化了一个默认关闭的已有传感器符号。

验证证据（本轮新鲜结果）：
- SDK 同版原生 BusyBox 运行 tests.test_a123x_board_debug：19 项通过。
- tests.test_a123x_debug_packages：5 项通过；包含包 hash 与实际缓存一致、损坏包拒绝、全新缓存准备、全工具依赖图无环、真实 libgpiod staging 的只查询安装集与 ELF 依赖。
- 上述合并运行 24 项，exit 0，无跳过；执行时显式绑定当前 SDK、脚本目录、BusyBox 和 libgpiod staging。
- tests.test_a123x_debug_services：21 项通过，exit 0，无跳过；显式绑定 USB/SSH/NETWORK 三脚本。
- 三板 SDK Kconfig：CB400_PERIPHERALS、F20_DEVWIRE、F20_EVT1 均解析出 PSI、trace、debugfs、libgpiod；关闭 AML_DEBUG 后不再选择这些新增能力，显式关闭 PSI/trace 的开发配置有效。
- 隔离 ARM64 kernel Kconfig：CONFIG_PSI、FTRACE、TRACING、EVENT_TRACING、TRACEPOINTS、DEBUG_FS、GPIO_CDEV、PINCTRL/PINMUX 和 C5 控制器为 y，PSI_DEFAULT_DISABLED 关闭。只做配置解析，不声称完成内核编译。
- 原生 SDK libgpiod 目标在独立 download/build/board/rootfs 路径完成交叉编译，exit 0。readelf 核验 gpiodetect/gpioinfo 为 AArch64，NEEDED 仅 libgpiod.so.3 与 libc.so.6；库仅依赖 libc.so.6；无 RPATH/RUNPATH，SONAME 与安装 symlink 闭合。均包含 Build ID。
- 真实 debug-install 规则的隔离测试验证工具、共享库哈希进入 tools.sha256 并全部校验成功。该安装规则测试的其他工具为 fixture，不等同于其 ELF 构建验证。
