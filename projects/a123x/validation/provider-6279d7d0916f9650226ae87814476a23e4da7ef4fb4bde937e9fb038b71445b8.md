# A123X SDK 修复与三板制品验证

## 修复范围

- R1：SC5336P SO 唯一由 linux/mbp/sensor 原生规则构建和安装，增加 SONAME。实验工具复用同一原生规则；正式镜像逐字节比较原生库经 SDK strip 后的产物。
- R2：产品 install 形成单一依赖链；通用 vendor 包显式 install 依赖 build，空 OUT 的并行安装验证通过。
- R3：Sensor 库与诊断工具分别使用 SDK Kconfig 选择；关闭功能不编译、不安装对应内容。产品 pipeline 模板随 Sensor 选择安装。
- R4：BCMDHD 原件和补丁迁到现有 common_drivers 无线驱动目录；配套数据放在 aml-tools/board/AP6303BH。运行模块使用 /amlogic/ext_modules，固件直接使用 /lib/firmware，配置为 /etc/wifi/bcmdhd.conf，来源为 /usr/share/bcmdhd/source-lock.json。F10 仅保留为供应商 provenance。
- R5：旧 native/brcmfmac 参考 bundle 退出默认构建、校验、安装和运行选择；历史原件保留为参考。删除旧隐藏开关及运行接线。
- R6：MBP 适配先执行 I2C_FUNCS、I2C_SLAVE，拒绝内核地址占用。MBP、ID、stream、RX 共用设备节点上的非阻塞 flock，持有至关闭 FD；失败无寄存器写入。该锁约束协作式用户态入口，不限制绕过协议的第三方。
- R7：产品配置模板归产品层；通用 sample 不复制 F20 模板。默认 pipeline 配置通过通用 Kconfig 字符串选择，去掉 CB400 板名判断。

显示与 Wi-Fi 诊断源码迁回现有 aml_commonlib 模块边界，Sensor 工具归原生 Sensor 子目录；无需新增 manifest 项。产品 f20-modules 只保留 metadata 和启动准入。默认 Wi-Fi 模式 disabled，硬件验证字段保持 false。

## 打包与升级规则

三个板型启用 SWUpdate 硬件兼容检查；使用独立 hwcompat 构建/安装缓存变体，实际链接戳依赖本地 vendor 库，避免缓存直达 install 绕过依赖。bulk stage 之后明确覆盖为所选变体。正常 rootfs 和 recovery 写入相同唯一板型 token，在签名前写入 sw-description；正则支持原模板冒号格式，并检查缺字段时拒绝打包。

独立 recovery DTB 使用通用 AML_OTA_SEPARATE_DTB 选择，本次三板启用；AML_OTA_DTB 与 AML_KERNEL_DTB 均进入镜像。全部 11 个 A123X defconfig 已隔离解析，其他旧板型保留原 boot-DTB recovery 行为。CB400 原 recovery 文件名不存在，改用当前实际 peripherals DTB。

AML_EMMC_SIZE 参数化 makegpt，格式限制为正整数 M/G，当前三板显式保持8G。此处是配置容量，未测量实物容量。

切板清理覆盖新模块输出；构建指纹覆盖 Kconfig、SDK规则、所选 defconfig 和相关验证工具。最终构建保存公开制品、配置及 hash，镜像门禁失败不能报告构建通过。
