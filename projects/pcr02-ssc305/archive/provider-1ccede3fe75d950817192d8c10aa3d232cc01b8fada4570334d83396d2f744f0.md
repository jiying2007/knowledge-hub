# PCR02 MSPI恢复与SDIO相位定向修复及STR适用边界

记录日期：2026-10-29。来源为本次工程会话的日志分析、release 源码对照与定向编译回执。
本记录为待复核候选，不证明现场故障根因、最终制品就绪或产品放行。

## 背景与日志结论

输入为 system_stuck.tar.gz 离线日志包。关键异常窗口为 2026-10-13 06:17:52 至 06:18:07。
保留的 Sensor 日志显示 Wi-Fi 恢复持续超时，TCPKA 重建失败并反复通过 RTC 重试，重试计数达到304。
末次循环中 MCU 辅助模块状态同步和 DISARM 命令各约6秒后返回 -65541，表示交互超时。
随后低功耗事务失败，恢复未完成；上层尝试恢复业务，显示 BLIT 报 errno=8。
导航、网络和资源采样线程仍有输出，因此不能据此判定整机已经死锁。

同期最后资源记录为可用内存约55.44MB、进程RSS约63.55MB，没有内存耗尽证据。
包内单独的资源TSV对应9月28日，缺少与10月13日故障关联的证据，不能混用。
MCU超时早于显示错误，不能以显示错误解释前面的串口超时。

## 已实施修改

1. MSPI保存实际应用的时钟分频和有效标记；resume重新应用已配置帧位宽与分频。尚未配置控制器保留初始化默认值。
2. 在SPI传输边界将-HAL_MSPI_TIMEOUT映射为Linux -ETIMEDOUT；HAL内部错误码、等待时长及BDMA取消语义不变。
3. SDIO的Linux/IP_SDIO/CLK_DU/已启用时钟相位分支中，BIT08按指定供应商源码修正：扩展相位置位、4相位清位。DTS相位、频率及开关保持原值。
4. 添加docs/LOW-POWER-SDK-PORT.md，记录代码契约、适用边界、验证与回退入口。

## STR与升级边界

供应商MIU PM arbiter/MIU2AXI复位和SPI_CLK输入设置位于CONFIG_SSTAR_PM_USB_SUSPEND_MODE专用路径。
当前PCR02配置不启用该路径，因此没有移植这些寄存器操作。未来改变电源域或启用该配置时，
需重新核验kernel、boot、pm_rtos、内存布局、引脚和板级唤醒线路。

release已有BDMA generation/cancel/IRQ同步、MSPI DMA长度与PIO保护、BCMSDIO唤醒锁修复、
ST77912及局部BLIT适配，不能被供应商原始SDK整体覆盖。
对照时release使用的BCMDHD为较新的101系列，指定SDK为较旧的100系列；SDK打包日期不能替代组件版本比较。
本次没有找到可直接证明修复MCU超时或Wi-Fi持续恢复失败的供应商UART/Wi-Fi补丁。
