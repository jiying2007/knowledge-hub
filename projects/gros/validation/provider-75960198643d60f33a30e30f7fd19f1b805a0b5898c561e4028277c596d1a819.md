## 具体问题

1. API src/api_network/api_wifi.c:3351-3371：wmg_status_t ret未按枚举类型前缀en命名，应为enWmgStatus；3354/3356分支无花括号，违反C规范强制要求；pcSsid==NULL、ret==WMG_STATUS_SUCCESS与常量在左的项目规则不一致。模块前缀VSAPIWIFI_和VS_CHAR/VS_S32边界本身正确。clang-format不会检查所有人工规范，当前该C文件格式替换为0不代表这些规则通过。
2. API include/api_wifi_persistence.h:1 guard为VS_API_WIFI_PERSISTENCE_H，项目C规范4.1及同目录api_wifi/api_ntp/api_tick/api_event使用__API_*_H__并带尾注释；应与本模块规范统一。此点已回读真正C规范，不从其他模块guard类推。
3. 新接口VSAPIWIFI_ConfirmNetworkSaved（同名WiFi/Linux层）是主动恢复priority/disabled、SAVE_CONFIG和sync，不是只读确认。建议新增尚未固化接口使用VSAPIWIFI_PersistConnectedNetwork / wifi_sta_persist_connected_network / linux_sta_persist_connected_network；注释仍须说明会保存整个station配置并恢复网络策略，目标SSID用于身份保护，不能把名字理解成仅写单一条目。若已对外发布该符号，重命名需明确兼容/调用方范围，不直接删除导出。
4. 老接口VSAPIWIFI_SaveNetwork(:3312)只memcpy重连上下文，日志(:3346)却称Network saved locally。旧符号为兼容应保留，公共api_wifi.h声明旁应明确“仅更新进程内重连凭据，不写配置文件”；日志应称reconnect credential updated in memory。无需为纠正文字再新增一层wrapper或状态机。
5. Sensor saved_network_cache_(:270)可在持久化失败后写入本地凭据，因此saved不能充当已落盘事实。建议内部改known_network_cache_及known_network_cache_updated_ms_等；from_backend仅说明来源，后端LIST_NETWORKS同样不证明磁盘已持久化。公共GetSavedNetworks/proto saved_networks为兼容可保留，注明运行时已知profile快照和来源边界。
6. Sensor retryConnectedCredentialSave(:2359)现在既执行首次尝试又执行重试，建议processPendingPersistence；saveConnectedCredential建议persistConnectedNetwork；save_connected_credential_generation_建议pending_persist_generation_，save_retry_generation_建议persist_retry_generation_，save_attempts_建议persist_attempts_，next_credential_save_ms_建议next_persist_attempt_ms_；局部saved（当前结果）建议persisted。三个动作分别是更新内存、查询运行时条目、主动持久化，不应全部叫save。
7. Linux linux_sta.h:28的read-only queries注释组中混入会修改状态的confirm_network_saved声明(:30)，应拆开写清副作用。日志link_preserved=true只能表达本操作未主动断链，不能作为本次物理链路仍在线的证据；宜用描述操作/连接结果是否更新的文字。

保留命名：WPA协议命令SAVE_CONFIG不可为风格重命名；公开历史SaveNetwork/GetSavedNetworks/proto字段不做无兼容计划的批量更名；wpa_restore_save_and_sync准确描述动作序列，可保留；文件名api_wifi_persistence.h与wifi_persistence.h名词语义合适。
