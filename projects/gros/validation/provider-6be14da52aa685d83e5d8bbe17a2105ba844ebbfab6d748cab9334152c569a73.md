# WiFi 暂停恢复与逻辑期限审查候选

状态：reviewing；当前仅为作者自审风险候选，尚未修复，不代表产品通过。

范围：PCR02 项目 Sensor、API 与 WiFi manager 的业务生命周期变更。硬件初始化和退出归生命周期 owner，Sensor 正常业务不执行 Reset。

结论：

- API 暂停后台采样时，重复 NET_CONNECTED 会使有效快照失效，且同值状态不触发主动采样。首次确认采样失败也缺少暂停期间的受控重试。
- Sensor 连接 deadline 只检查 pending 请求；已提交、物理调用已返回而联网确认持续不可用时，逻辑连接标志缺少期限终止，可能持续阻挡休眠。
- 集中采样复用的共享状态 helper 有未加状态锁的写入，与公共 getter 和 clear 的加锁写入不互斥。此为既有 helper 债务，本次采样架构仍需补齐局部采集与原子提交。
- Recovery Host 测试未自动跟踪公共头依赖；现有二进制可能被错误视作最新。部分 API C 命名、声明与大括号规则以及 Sensor 新增格式尚未满足模块规范。

证据：全新输出路径重新构建的 Sensor 两程序与 recovery 三程序 ASAN/UBSAN 通过，静态契约 21 项通过。两个包含真实实现的 Host 负向用例分别确认同值通知导致快照不可用、已过期 submitted 请求保持逻辑进行中。头文件变化 dry-run 确认漏依赖。并发项来自源码同步分析；主机缺少 TSan 库，没有动态 TSan 报告。

下一步：API 先统一暂停下的确认采样和共享状态提交契约，Sensor 再补 submitted 的逻辑终态；物理调用未返回时保留所有权与保守门禁。随后修测试依赖与增量规范，再做独立审查和产品集成验证。

边界：本轮没有修改产品源码，没有最终链接、部署或板端 HIL。不能把 Host 通过当作 SDIO 恢复、TCPKA 或休眠唤醒通过。同步 vendor 调用不返回时的退出上限、缺少操作身份的迟到事件仍需明确接受或升级处理。
