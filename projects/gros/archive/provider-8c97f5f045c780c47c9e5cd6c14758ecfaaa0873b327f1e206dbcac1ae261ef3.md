## 结论与证据等级

1. 已确认：10 月 17 日 16:32 离线起点是手动立即 OTA 接管、应用有序退出；16:47 和 17:08 是电源键关机事件，未见崩溃证据。不能把这些退出归因于 AP 踢下线或状态解析抖动。

3. 强候选：凭据持久化/启动恢复链路异常。尚不能区分保存失败、路径或挂载不一致、配置被覆盖/清理、网络列表或安全信息读取不完整。缓存 count=0 只证明查询视图为空，不能单独证明磁盘凭据丢失。

5. 未复现：现有覆盖内未检出旧的约 1 秒 ERROR→NET_CONNECTED 状态抖动，也未检出已连接运行中 LINKED→UNLINKED/NETWORK DOWN 或 MQTT CONNECTED→DISCONNECTED 的记录。缺少记录不等于全时段绝无物理断链。

## 保存网络异常：现象、候选与代码缺口

已见事实：

- 三段 Sensor 的 state=2、count=0 缓存返回一直持续到重新扫码；成功后变为 state=6、count=1。
- 三次 boot_id 不同，说明至少这三段跨内核启动，而不是同一进程的短暂状态抖动。
- Task 三次都记录 /data/task/wifi.toml 不存在。这是 Task 配置文件，不等于 supplicant 的持久化文件，不能单凭此条宣布底层凭据被删除。
- 包内 data/etc/wpa_supplicant.conf 为 0 字节，hostapd.conf、p2p.conf、dnsmasq.conf 同样为 0 字节；未提供采集机制、是否占位/脱敏、设备 symlink 与挂载身份。因此不能把打包文件的零长度直接当作运行时实际配置内容。
- 未见清空网络/解绑/恢复出厂的直接事件，但轮转与系统日志缺失限制了这个负面结论。

源码核对：

- Sensor 当前与 6935f84 历史版本的 getSavedNetworks 都区分 prefer_cache 与直接 API 查询。非过渡态且 prefer_cache=false 时会读 API；handleMonitorState 在无保存网络时定期直接复查。因而不能仅凭缓存 count=0，声称“空缓存一旦有效就永远不查询”。
- 当前 WiFi linux_sta.c:1610-1616，在选择网络前 SAVE_CONFIG 失败仅记录 warning 后继续。
- 当前 linux_sta.c:2722-2730，连接成功且 SSID 匹配后调用 wpa_conf_enable_all_networks()，未检查其返回值；该函数 linux_sta.c:916-940 内部 SAVE_CONFIG 失败确实返回 FAIL。
- 这是已核实的源码可观测性/错误传播缺口：连接成功不保证凭据保存成功。它与“扫码即连上，重启后无法恢复”的表现相符，但未取得现场 SAVE_CONFIG 返回值、系统 errno、配置路径及内容摘要，不能宣布是本次根因。
- API 当前 _WIFI_EnsureSupplicantConfig() 仅在 /etc/wpa_supplicant.conf 不存在时创建默认头；若文件存在但为空不会补写默认配置。这是待复核的配置入口边界，不建议无证据自动覆盖用户配置。

优先补证/改进：读取实际配置路径、readlink/mount、文件存在/大小/权限、ctrl_interface/update_config 是否存在、network 块数量，全部只输出脱敏摘要；记录 SAVE_CONFIG 返回与持久化阶段结果，将 link-ready 和 saved-for-reboot 分开表达。不要通过持久化失败把当前可用链路直接伪装为断开。

## 弱网策略与 ACK 问题

- 三次请求 Sensor 均 linked=false、空 SSID、RSSI=0、generation=0，返回 -4，耗时约2ms；见 sensor.log:1877-1879、2483-2485、3008-3010。
- Task 的 request.cpp 同步记录 ACK failed，随后 wifi_ctrl.cpp 又报告 sent successfully；见 task.1.log:3462-3464、4229-4231、4918-4920。
- 六次进入 NetCfg 见 task.1.log:3474、3579、4241、4396、4569、4930。并非六次新的物理断开。
- 对已保存网络为空/未知、首次启动等待恢复、恢复中、真实弱信号应分别处理。RSSI 无效不能以0作为信号值累计 severe-weak 时间；失败 ACK 不应记成功或消耗成功切换的冷却窗口。
- 当前用户授权范围为 Sensor/API/WiFi；Task 不在修复提交范围，本次只记录它的日志问题和依赖关系。
