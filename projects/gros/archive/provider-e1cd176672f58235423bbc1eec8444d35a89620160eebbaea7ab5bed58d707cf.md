# F10 出海固件实施方案

日期：2026年10月16日  
适用范围：F10／SSC305，美国首发及中英文资源支持。

前置条件：《出海固件端方案选型》（来源内引用：`出海固件端方案选型.md`；尚未映射为 Hub 链接）完成评审，在固件固定、产线写入、APP设置三种国家方案中确认一种，并明确云环境、时区、资源方式及OTA路线。本文国家读写部分按推荐的产线方案编写；如最终选择固件或APP方案，须先同步国家来源、权限、启动及验收内容，再按确认结果实施。资源方案一、方案二分别对应所选发布方式。

## 1. 总体方案

采用产线国家属性、现有云环境选择、扫码同步时区、网络补全时区和签名OTA。中英文资源提供全量随固件打包、按国家组织并独立更新两种方案，产品发布时选择其中一种。

设备国家属性区分CN、US，无线国家码及默认资源语言由该属性确定：CN对应中文，US对应英文。Task／IoT根据国家属性与data中的现有正式／测试环境配置选择云服务。时区由扫码或网络同步，独立于国家和云环境。软件复用现有出厂存储、配置解析、配网、时间服务、资源播放和升级执行链路。

## 2. 分区与仓库

| 分区 | 内容 | 更新方式 |
|---|---|---|
| customer | 应用、运行库、已有硬件配置、所选方案的预装资源、时区数据、验签公钥 | 随固件更新 |
| factory | 国家属性、设备身份、校准数据 | 产线或受控工装写入 |
| data | 现有正式／测试环境配置、账户、网络、时区、业务数据，以及方案二的更新资源 | 应用按文件更新 |

仓库分工：

- `ota_f10`：SDK镜像组装、SoC及整机升级包、发布清单与签名。
- `app_ssc305`：应用发布输入、运行库及预装资源；方案一保存完整中英文资源，方案二按国家选择预装内容。
- 方案二的独立资源目录或仓库：维护可独立发布的资源、清单及资源包。

customer镜像由SDK底包与发布清单选择的应用、库、资源共同生成。发布清单仅安装指定文件，并明确资源方案。普通固件升级保留factory和data；方案二的资源更新只写指定资源目录。

## 3. 国家属性、云环境与产线

### 3.1 国家与环境

国家和云环境分别管理：

| 字段 | 含义 | 来源 |
|---|---|---|
| country_code | 产品销售／使用国家，CN或US | factory出厂参数 |
| cloud_env | 正式或测试环境的业务含义 | data中现有Task／IoT配置，沿用原字段与枚举 |
| Wi-Fi ccode | 无线驱动使用的国家码 | 由country_code映射并核对实际值 |

当前CN、US均采用一对一映射，country_code为唯一持久化国家属性，Wi-Fi层使用对应ccode，资源层选择中文或英文。

Task／IoT继续管理app_id、mqtt_endpoint、token_endpoint、ota_endpoint等，按country_code和现有cloud_env共同选择合法服务组合。生产／测试切换不改变国家、无线国家码、资源语言或时区；服务组合统一重载，不能混用不同环境的地址和凭据，按现有方式生效。

中国正式、中国测试、美国正式、美国测试是四种逻辑组合，不要求四套固件。国家固定在制造侧，云环境由已有data配置选择。生产出厂显式确认正式环境；release／debug构建类型与云环境分别表示。

customer中的app_config.ini继续保存其原有硬件／功能配置，不增加国家和云服务字段，也不整体迁到factory。

### 3.2 写入和启动

国家属性复用MAC、SN所用的FactoryStore读写机制。新增一个独立的小型出厂参数记录，保存country_code；复用双槽、CRC、序号、原子写入和锁定能力。MAC、SN、密钥继续由设备身份记录管理。

产线通过统一出厂参数接口写入CN或US，回读并重启验证。Sensor出厂参数服务统一承接读写；其他进程通过现有消息／接口读取。跨进程写入必须统一到该服务，不依赖FactoryStore的进程内锁。

启动顺序：挂载factory并读取国家属性，确认无线国家码，读取data中的现有云环境，加载用户设置和资源，启动联网及云业务。首发美国镜像无线默认值为US；中国镜像使用CN。首次联网前核对实际值，固件支持国家与出厂属性不匹配时拒绝依赖业务。

国家未写入、记录损坏、非法值或驱动值不匹配时，停止依赖的联网和云业务，保留充电、电机安全、watchdog和工装修复能力。cloud_env缺失／非法按现有Task／IoT规则处理，生产出厂检查不得让设备意外进入测试环境。普通恢复出厂保留国家、设备身份和校准数据；云环境按业务规定重置，不能意外沿用测试值。

## 4. 时区与时间

### 4.1 扫码同步

APP读取手机系统时区，在现有配网二维码中增加 `timezone_id`：

```json
{"timezone_id":"America/New_York"}
```

传递IANA地区时区名称。设备校验长度、允许形式及本地规则文件，随成功的配网／绑定配置一并提交。配网失败不覆盖原时区；时区字段缺失或无效不撤销已成功的网络配置。

时区写入现有 `/data/task/user_config.toml`，由用户配置所属模块统一写入，其他模块通过接口提交修改，保留文件中的其他配置项。配网结果返回当前时区、来源、保存结果和生效结果。

### 4.2 网络补全

设备没有有效时区时，通过云接口获取：优先返回设备已登记的安装地时区，没有登记值时可根据设备出口IP推断。返回内容为IANA时区或明确的未知结果。

优先级如下：

1. 本次成功扫码提供的合法时区。
2. 设备已保存的合法时区。
3. 网络补全得到的合法时区。

网络结果提交前再次检查当前绑定和时区来源。请求期间已完成扫码设置、解绑或恢复出厂的，丢弃失效响应。网络结果不覆盖APP已设置的时区。

缺值时在联网后请求，超时5秒，失败后间隔60秒重试，每轮最多3次，随后等待网络恢复或用户同步。断网保留已有时区；设备搬迁后通过重新扫码或明确同步更新。

### 4.3 系统生效

系统时钟使用UTC，RTC和网络校时维护系统时间；时区数据负责本地时间及夏令时转换。分别报告系统时间是否就绪、时区是否有效。

时区数据随固件安装到 `/customer/share/zoneinfo`，包含销售地域所需规则和别名。用户配置保存唯一有效时区ID，System据此生成 `/data/system/localtime` 链接；新出厂rootfs中的 `/etc/localtime` 指向该链接。

相关进程在启动时加载统一时区，运行中更新时刷新本进程时间转换和业务计划。使用文件接口和标准时间接口处理，校验规则文件有效性，任何保存或应用失败均返回错误。重启时从用户配置重建运行状态。

### 4.4 定时业务

- 日历任务在系统时间和时区均就绪后运行。
- 春季夏令时跳过的槽位，本次不执行。
- 秋季重复时间，同一规则、同一日期、同一计划槽位执行一次。
- 不同规则、不同槽位分别处理，重启后保留去重状态。
- 校时或修改时区后安排下一次合法任务，不集中追补过去的动作。
- 间隔任务保持原有频次、工作窗口和安全条件，寻宠90分钟重试不受日历去重影响。

## 5. OTA安全与执行

### 5.1 发布文件

保持现有升级包内部结构，随包发布两个文件：

| 文件 | 内容 |
|---|---|
| 原升级包 | 整机包或SoC包，包含现有载荷和升级脚本 |
| `ota_manifest.json` | 包类型、产品、板卡、布局、生产渠道、支持区域、配置格式版本、组件版本、包名、大小和SHA-256 |
| `ota_manifest.sig` | 对manifest原始字节的数字签名 |

签名固定使用RSA-PSS／SHA-256，RSA密钥2048位，MGF1-SHA256，salt长度32字节。设备预置发布公钥，私钥由发布端保管。发布端与设备端使用成熟密码库，完成同一套签名样例的互验。

manifest使用UTF-8，拒绝重复键、缺失必需字段、非法包类型和超限内容。生产设备仅接受生产渠道及匹配产品、板卡、布局和区域的包。签名绑定manifest，manifest中的大小和SHA-256绑定整个原包。

### 5.2 升级流程

1. 获取manifest及签名，验证签名和适用条件。
2. 取得完整升级包，校验大小和SHA-256。
3. 在专用目录安全解包，核对组件及guide信息与manifest一致。
4. 确认执行器、依赖和载荷在customer卸载后仍可用。
5. 交给现有升级执行器停业务、写入并记录结果。

验证完成前不执行包内脚本。执行时使用本次校验后的同一包和隔离目录，防止中途替换。解包拒绝路径越界、非法链接、额外执行项及超限展开。

所有生产开放的升级入口统一验证。空间不足、验签失败和不适用包在停业务前拒绝；写入失败返回真实失败。普通升级不覆盖factory和data。

### 5.3 版本与结果

选中组件分别查询当前版本，按各组件版本协议比较。禁止组件降级，至少一个组件升级，其余可保持同版本，允许合法的仅MCU或轮电机升级。

同一包重复请求根据实际升级状态处理；相同版本不同内容拒绝；当前版本无法确定时拒绝对应升级。升级成功以写入流程成功为准。

## 6. 中英文资源方案

### 6.1 共同规则

country_code决定默认资源语言：CN选择zh-CN，US选择en-US。正式／测试环境使用相同的国家语言规则。资源清单按逻辑ID记录用途、语言、文件和是否属于离线必需资源，消费者通过统一资源入口读取。

动物声、白噪音等通用内容只保存一份。启动、配网、必要故障和恢复操作所需资源必须出厂可用，首次使用不依赖网络下载。目标语言的必要资源缺失视为发布错误，运行时明确报错，不静默播放另一种语言；可选内容缺失只影响对应功能。

### 6.2 方案一：中英文全量随固件打包

将完整中文资源、英文资源和通用内容全部打入customer。语言资源按zh-CN、en-US分别组织，通用资源单独保存。设备启动读取country_code，建立对应语言的资源映射；相同逻辑ID在中文和英文中对应各自文件。

应用与两种语言资源作为同一固件版本发布，资源修改通过固件OTA交付。此方案不启用data资源更新层。

优点是离线完整、运行路径简单、应用与资源版本一致，产线无需额外安装语言包。代价是customer占用和固件升级包较大，即使只修改一个提示文件也要发布固件。

全量中英文资源不代表必须使用完全相同的CN／US镜像；无线启动配置仍按目标国家生成。发布前分别核对中文、英文资源清单及逻辑ID映射，不能仅检查文件总数。

适用于完整中英文内容能够装入customer并保留容量余量、资源变更较少且优先降低运行复杂度的发布。

### 6.3 方案二：按国家预装，指定资源独立更新

沿用现有resource目录及资源清单的业务组织，由构建按country_code选择对应中文或英文文件，不强制重排全部目录。customer安装目标国家的预装资源和通用内容，包含完整离线必需集合；无需随固件携带另一种语言的完整文件。

对需要独立更新的声音或内容单独生成资源包，安装到data。未列入独立更新范围的文件继续随固件发布。资源包记录产品、国家／语言、资源类型、版本、资源格式版本和文件清单，并使用签名及整包哈希校验。

读取顺序为：已激活且国家、资源类型、格式版本与应用匹配的资源包；清单允许时使用customer预装资源。按资源包和清单选择，不按单个文件是否存在任意覆盖。模型、导航参数、校准和证书按各自业务管理，不混入普通音频包。

更新流程：下载到staging，检查签名、哈希、国家／语言、格式版本和容量，安全解包为完整版本目录，同步后原子切换活动清单。保留当前及上一有效版本；播放中的消费者固定使用原版本，结束后释放，未释放版本不得删除。安装器只写指定资源目录，拒绝脚本、可执行文件、特殊节点及越界路径或链接。

断电、满盘、损坏包、错误语言或安装失败时保持当前有效资源。每次启动及固件升级后重新检查活动包，不适用时选择上一适用包或customer预装资源。普通固件OTA保留data资源。

优点是固件只携带目标语言内容，指定资源可独立发布；代价是需要资源包版本管理、data空间、激活与回退检查。空间预算包含下载包、解包、当前包、上一包和业务数据。

适用于资源仍会持续调整，或双语全量固件容量、下载成本较高的发布。

### 6.4 两种方案对比与选用

| 项目 | 方案一：全量随固件 | 方案二：按国家预装并独立更新 |
|---|---|---|
| 预装语言 | 完整中文＋英文 | 当前国家对应语言 |
| 语言选择 | country_code映射 | country_code选择预装及适用资源包 |
| 离线首用 | 两种语言完整可用 | 目标语言必需资源完整可用 |
| customer／固件体积 | 较大 | 相对较小，取决于独立更新范围 |
| data资源空间 | 无更新层 | 需要下载、安装和回退空间 |
| 资源修改交付 | 固件OTA | 指定资源单独更新，其余随固件 |
| 运行复杂度 | 低 | 增加资源包校验、激活与回退 |
| 主要验收 | 两种语言清单、映射、镜像容量 | 国家匹配、包完整性、空间及异常恢复 |

发布清单明确选择方案一或方案二，不同时启用两套资源发布路径。双语完整镜像容量满足且资源变更少时选择方案一；明确要求部分资源独立热更新时选择方案二。依据当前存在独立更新需求，建议量产采用方案二，方案一作为全量资源发布选项保留。

## 7. 生产镜像与调试

生产镜像关闭SSH、ADB、Telnet、串口shell及危险应用命令，按生产策略关闭Bootloader交互入口。保留MCU通信UART和必要的脱敏错误日志。

普通SD配置不能开启生产shell。制造和售后使用受限工装，支持修复区域配置及导出必要诊断。

入口修复必须进入实际boot、rootfs和customer出厂镜像。发布前核验启动脚本、串口、网络、USB、SD及重启行为。AP脚本和hostapd配置移除前确认扫码配网流程不依赖它们；非关键旧文件清理失败只告警。

## 8. 构建与发布

发布采用固定的源码、工具链、sysroot、SDK底包、应用、配置和资源组合。产物标识包含产品、板卡、国家、云环境、渠道、资源方案、组件版本及哈希。云环境按现有data配置选择，发布清单记录出厂默认值。

先完成应用发布输入，再按所选资源方案生成customer、SoC包、整机包和签名文件。方案一打入完整中英文及通用资源；方案二打入目标国家预装资源，并单独发布需要更新的资源包。

发布检查包括：US区域和无线值一致、英文基础资源齐全、组件和guide一致、签名有效、生产入口关闭、普通升级保留factory/data，以及实际镜像与发布清单匹配。

## 10. 验收标准

| 项目 | 验收要求 |
|---|---|
| 国家属性 | 未写入、非法、记录损坏或国家不匹配时拒绝依赖业务，安全控制继续；写入断电不破坏身份和校准 |
| 国家／环境 | CN正式、CN测试、US正式、US测试分别核对服务组合；切环境不改国家和ccode，普通恢复出厂不误进测试环境 |
| 扫码时区 | 成功配网正确保存；失败不覆盖；非法时区不撤销网络成功；凭据不进入日志 |
| 网络补全 | 缺值时补全，超时或未知不误设；迟到响应不覆盖新扫码值或新绑定 |
| 系统时间 | 只读系统、多进程、断网和重启行为一致；保存与生效结果真实 |
| 定时任务 | 夏令时缺槽和重槽处理正确；重启不重复；间隔寻宠频次保持 |
| OTA验证 | 签名、manifest或原包篡改均在执行脚本或擦写前拒绝；错误产品、区域、渠道、布局和版本拒绝 |
| OTA执行 | customer卸载后正常执行；同包重试不误报；组件版本及部分失败结果真实；factory/data保留 |
| 资源共同项 | CN选择中文、US选择英文；切正式／测试不改变资源语言；断网首启、配网和必要故障提示齐全，通用内容不重复 |
| 资源方案一 | 镜像含完整中英文和通用资源，逐项验证两种语言映射；customer及升级包容量满足；未启用data资源覆盖 |
| 资源方案二 | 按国家预装正确语言；独立包国家／语言不匹配、越界或损坏时拒绝；满盘、断电及播放中更新保持有效资源；固件更新后重查资源格式版本 |
| 生产入口 | 网络、USB、串口、SD和应用调试入口关闭，MCU UART及受限工装正常 |
| 发布身份 | 源码、镜像、应用、配置、资源、组件版本及签名包可追溯且相互一致 |

交付以目标板验收报告为准。开发完成、构建成功和包生成分别记录，不能替代设备上的功能、失败恢复及升级验证。
