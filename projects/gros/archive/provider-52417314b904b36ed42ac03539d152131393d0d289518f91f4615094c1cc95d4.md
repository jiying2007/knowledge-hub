状态：UNPROVISIONED / INVALID / VALIDATED / APPLYING / ACTIVE / APPLY_FAILED；保存值和运行值分别可观察。资源状态：ABSENT / STAGED / VERIFIED / ACTIVE / REJECTED。时间状态分 UTC 是否可信与安装地时区是否已确认，不用一个布尔值混合。

边界例：US+ccode CN 拒绝区域应用；仅切英语不改云；时区未知时不运行依赖本地时间的计划任务；更新失败继续使用旧有效资源；错误区域包在 quiesce/擦写前拒绝；关闭调试串口不关闭 MCU_UART。

## 4. S1 区域与启动方案

1. 共用源码，显式发布 F10/SSC305/板级/US/production 组合，禁止从缺省 CN 或默认中文推断 US。
2. 首发产物将 customer 中 Wi-Fi 默认配置设为 US；产线注入同区域完整 INI；两者不一致拒绝无线联网及云业务，保留本地诊断/修复入口与安全控制。
3. 挂载 factory -> 读取/校验快照 -> 在联网前应用无线配置并读回 -> 启动 IoT/Task 相关服务。不得以“业务稍后修正”掩盖驱动先按错误区域启动；首发静态 US 值承担该约束，后续通用镜像需验证预连接动态能力。
4. app_config 模块建立在 api_config 既有解析之上，不再实现另一套 INI parser。公共接口提供受校验快照与真实状态；更新接口按字段权限控制。api 内仅提供通用配置机制，F10 字段及策略由产品组合层定义；不得把云产品策略硬编码成平台通用 API。
5. 产线写同目录临时文件，校验、文件同步、原子 rename、目录持久化及回读；避免并发 writer，覆盖失败不发布半文件。首发采用重启生效，响应明确区分已保存与已生效。
6. factory 缺失/损坏时不回退 CN/GLOBAL；停止依赖此配置的业务，不停 watchdog、充电/电机安全或必要恢复通道。配置修复不能依赖已被阻断的云连接。
7. 普通用户恢复出厂清除账户、Wi-Fi 和用户偏好，不清设备身份、校准、区域及安全高水位；返厂改区域采用独立受控流程。
8. APP 当前仅允许选择国家码时，将其定义为受校验服务/安装区域意向，不直接覆盖设备出厂区域；冲突明确拒绝或进入受控迁移。首次配网传输通道与移除 AP 脚本的兼容性必须由 APP/IoT owner 确认。

S1 验收：CN/US 及不一致、缺失、重复键、非法 endpoint 组合、断电、空间不足、重启、OTA 保留；首次联网前的无线实际值有板端证据。字段/节名、最大长度、必填项、未知项保留、重复项拒绝、错误码与并发写策略全部冻结。

## 5. S2 时间、时区及夏令时

- 系统时钟存 UTC；业务本地时间按 IANA 时区转换；持续时长/超时用单调时钟，不靠墙上时间差。
- 时区源优先级：设备已确认的安装地设置 > 同地点配网时经确认的手机系统时区候选 > 位置/IP 仅推荐。手机远程管理、旅行、拒绝定位或近似定位不能自动改变设备时区或云归属。
- 若 APP 协议确实只有国家码而无时区/安装地数据，US 时区不能唯一确定。必须增加可选 timezone_id 元数据或由云端设备设置提供；未确认前相关定时任务明确不可用，基础手动操作仍可用。
- 随系统提供首发支持范围内完整规则的 tzdata；如果覆盖美国销售范围，清单不能只含 New_York/Los_Angeles，须按销售地域确认 Phoenix、Alaska、Hawaii 等覆盖。时区包可独立版本管理，但首发可随系统/固件提供，不强制增加热更范围。
- /etc 只读时使用预先设计的链接/运行态配置位置；持久设置归入既有 /data 用户配置，由唯一 writer 管理，不另造第二套优先级。多进程启动取得统一值；运行中更新由各进程显式重载并回报，不能认为某进程 tzset 就代表全系统生效。
- 修复旧 setter 的 shell 拼接、路径校验、失败返回、目标文件存在和多进程生效语义，再对外开放。只接受白名单 IANA ID，不把 APP 字符串拼入命令或路径。
- 定时任务语义建议：春季跳过的时间执行明确的跳过策略；秋季重复时间每个任务在该本地日最多执行一次，持久去重；切换时区/校时时重算未来触发，不追补危险动作。该策略须 Task/product owner 冻结，不能由 System 单方决定。
- 启动未校时、RTC 失效、NTP 大跳变、休眠恢复及离线都单列。签名元数据有效期不能独立依赖未可信的设备时间。

S2 验收：DST 前/后、重复/不存在时间、跨日、时区切换、重启、NTP 跳变、长期离线与休眠唤醒；Task 的寻宠、工作时间、回充分别给业务结果。Host 可注入时间，不改开发主机系统时钟。

## 6. 资源布局、仓库与热更新

customer：程序/动态库、必要的离线英文启动/配网/故障提示，必要通用资源、基础清单、信任公钥。factory：出厂区域/身份/校准，各自独立文件和权限。data：用户状态、资源包、暂存/激活记录及可重新下载内容。

语言化提示音与动物声/白噪音分包：locale/zh-CN、locale/en-US 与 common/content。AI 模型、KWS、导航参数、校准及 TLS 信任库不作为普通声音包一起更新；分别冻结 ABI/模型或信任契约。

优先统一 ResourceResolver：逻辑资源 ID -> 已激活兼容包 -> 明确允许的 customer 基础资源。每次播放/业务序列固定包快照；不能按文件存在任意混合 data/customer。增量包必须声明 base hash，缺失/损坏时回退整个有效组合或指定关键兜底。

旧路径适配可在有限资源子目录使用只读 bind mount/链接；只在必要时用局部 OverlayFS。不得将整棵 customer 调试 upper 用作生产更新层；其旧文件与 whiteout 会遮挡新固件资源，且现有固件版本变更归档 upper 的规则与独立资源生命周期冲突。挂载切换对既有 FD 和进程缓存不保证立即生效，需入口快照/重载契约。

资源更新：下载 staging -> 验签及全文件哈希/兼容/大小校验 -> 同文件系统完成版本目录持久化 -> 原子切换激活清单 -> 新请求使用新包。保留当前及上一有效包，GC 仅删除未引用且非活动包；满盘时先拒绝新更新，不损坏当前资源。不在活动目录就地覆盖。

新增 resources_ssc305 或等价独立资源发布仓，管理资产、语言映射和清单；较大二进制可用受控制品存储、Git 管清单/来源/版权及哈希，避免 Git 无限膨胀。无需创建“整个运行态 data 仓库”；若确需出厂 data 默认文件，另建受限模板，绝不携带用户运行数据。

首发不重划分区；容量准入至少覆盖：当前有效包、上一包、候选解包、下载包、日志/业务保留及闪存余量。实际峰值须依实现测量，不能把 140 MiB 全视为可用。普通固件 OTA 保留 data；资源包走文件级更新。

## 7. S3 调试与生产镜像

生产镜像关闭网络 shell、ADB/Telnet、串口 shell、Bootloader 交互/启动绕过及 Bridge 任意命令执行，逐项验收；Serial 在本需求中特指调试控制台，不影响 F10 MCU 通信。日志输出与交互入口分开，必要错误可保留脱敏诊断。

不能以端口扫描替代全部入口验证：需覆盖 Wi-Fi、USB、串口、SD 开机/热插拔、恢复模式和重启。现有普通 SD debug.ini 不满足授权来源验证，首发生产不得仅凭其开启 shell。调试固件与生产固件分别命名、清单、签名/发布资格，生产渠道拒绝调试包。

受控维护优先导出脱敏诊断；确需 shell 时采用设备绑定、nonce、防重放、限定能力、短时授权令牌，验证成功后进入临时会话，断连/超时/重启关闭。准确权限、可信时间条件、离线维护、密钥撤销与失败响应由安全/Bridge/System 共同冻结。现有脚本可复用服务控制，不能复用无鉴权开启条件。

rootfs 现有 inittab 直接 shell 必须修复并重生源镜像。远端 OTA 打包器当前不支持 rootfs 更新，需单列受验证系统基线发布或增加明确的按分区 rootfs 支持；不能只发布 customer 就宣称系统入口已关闭。旧 static customer 设备更不能直接套用当前 dynamic UBIFS 路径。

## 8. S4 可信 OTA 与整机版本

首发目标是软件层可信更新，不宣称等价于硬件安全启动。先由 BSP/供应商核具体料号/板级/BootROM/熔丝能力、现有制造流程与可启用性，再决定量产信任根。禁止执行任何 OTP 烧写或读改测试作为本轮分析动作。

建议发布 detached signature + 精确字节 manifest：签名绑定 product、board、region/support_regions、channel、布局、release_id、security_epoch/release_seq、最低 updater、SoC/MCU/轮电机版本、全部 payload 和包内脚本的哈希及大小、依赖/兼容关系。确定算法及现有库 provider 后冻结一种编码与验签合同；优先复用已审计库，不自研密码算法。MD5/CRC 可保留旧协议用途，但不承担真实性；裸 SHA256 sidecar 同样不承担来源认证。

信任公钥预置在受控固件信任存储，包中 key_id 只选择已信任密钥，不能接受包自带任意新公钥。私钥由发布/安全侧持有，端侧不得持有；固件负责公钥加载、版本/撤销、轮换验证与失败语义。不能以“密钥归上层”省略设备侧信任材料职责。新 key 需经已有信任授权，失信恢复路径单列。

设备顺序：有界读取 manifest/签名 -> 基于固定信任验签 -> 核产品/板级/区域/布局/版本策略 -> 安全解包至隔离目录 -> 核全文件清单/哈希 -> 进入 quiesce 与写入。任何包内 before_update/ota_start 脚本只能在此前验证后执行。拒绝路径穿越、绝对路径、越界 symlink/hardlink、额外文件及解包膨胀；验签后至使用之间防止文件被替换。

整机包覆盖 SOC、MCU、轮电机和脚本，同样保护 SOC-only、SD、本地恢复等可用入口。升级顺序按组件兼容矩阵决定；发生部分成功时记录真实组件版本，按经过授权的恢复路径继续，不虚报整机原子回滚。

软件防降级使用持久化高水位与升级日志，目录独立于可清用户状态/校准且普通恢复出厂保留。损坏时不得默认为 0；正常升级、同版本重装、降级、版本缺失、跨区域及紧急恢复分别有决策表。写入顺序需覆盖断电窗口，防止计数提前更新使合法恢复包被挡；高水位策略不等价于硬件抗篡改。

保持既有升级成功语义：写入流程成功即可报告升级成功；重启后验证作为发布测试证据单列，不新增 PENDING_BOOT 产品状态机。资源激活的保存/生效状态另行定义，不混用固件升级结果。

首个可信 updater 的引入需要受控制造/维护或现有可信路径；旧未验签 updater 不能靠新包自带签名自动变可信。普通 OTA 维持 factory/data 保留，整写 ubia 仅限明确接受覆盖并有备份/恢复的工装流程。

安全参考：TUF 的签名元数据/可信根延续/版本回退防护可用于设计检查，不宣称本项目已经完整实现 TUF。https://theupdateframework.github.io/specification/v1.0.36/

## 9. Sensor、数据与整机依赖

Sensor 不另建“海外传感器重写”大包，但必须承担新增资源路径/语言选择、区域配置消费及安全维护对启动/休眠的必要适配。国内出货证据仅在同硬件、同源码/库、同配置和同使用条件的可比部分复用。

F10 能力表包含摄像头/麦克风/扬声器、Wi-Fi、红外、IMU/ToF、显示、MCU UART、按键、激光、RTC/低功耗。回归至少覆盖首次配网、断网、云延迟、音频语言切换、OTA quiesce、寻宠/回充、休眠唤醒、生产/维护模式和存储压力。

数据最小化与隐私审查由产品/安全/云侧确认摄像、音频、遥测、日志、崩溃与第三方 SDK 的实际出境/留存/删除策略；固件交付真实采集/发送清单和关闭行为，不能仅因国内验证过就宣称海外无增量。美国无线及产品认证、第三方服务可用性、APP 上架等作为外部 owner 验收线，本方案不提供法律符合性认定。

## 10. 发布组合与迁移

发布锁至少包含 GROS 根与各独立模块 commit、dirty tree/patch 指纹、工具链与 sysroot、SDK 源镜像哈希/来源、copy-plan、板卡/profile/区域/语言/云环境、最终 SoC/整机/资源包哈希、签名 key_id 与组件版本。GROS 仅做编排，不把项目策略侵入通用模块 ABI。

固件版本继续写 customer/etc/version.ini；禁止无约束拼接 us_v 字符串后直接作为版本比较值。区域与版本独立表示，展示 tag 可有区域，比较用结构化版本/安全序号；生产配置不允许 unknown SDK 来源。

出厂、普通 OTA、整机 OTA、SD、返厂整写分别有矩阵：普通更新不覆盖 factory/data；资源更新仅指定目录；旧 static customer 到 dynamic UBIFS 独立迁移；整写 ubia 必须明确覆盖范围。rootfs 安全修复不得通过仅 customer 包宣称完成。

app 编译、release/app 输入更新、customer 重生、SOC 包、整机包、签名是不同阶段；后编译 app 不会改变既有镜像。发布前检测调试入口、AP 旧文件、中文残留提示、资源覆盖与区域/版本一致性。AP 文件移除先验证现有首次配网实际通道，旧 data 文件清理失败仅告警。

## 12. 验收矩阵与停止条件

1. 配置：缺失、非法、不匹配、部分写、满盘、只读、并发、断电、恢复出厂；不静默跨区域。
2. 无线：冷启动首次联网前 country、重连、驱动重启、休眠恢复、普通 OTA 后；US 实际值与使用信道/目标认证边界由负责团队核验。
3. 云：错误区域/错误 profile/错误证书、离线和高延迟、手机远程管理；不因定位漂移换云。
4. 时间：各销售时区、DST、校时跳变、无可信时间、重启/离线/休眠；计划任务无重复危险动作。
5. 资源：断网首启、英文必要提示、语言切换、缺文件/损坏/不兼容包、断电/满盘、升级后不被旧资源遮挡；AI/KWS 等不混为普通包。
6. 维护：生产负向、调试包拒绝、普通 SD debug.ini 无效、令牌错误设备/过期/重放、断连重启关闭、UART 业务不受影响。
7. OTA：签名/manifest/payload/脚本任意篡改均在写入前拒绝；错误产品/板卡/布局/区域/版本；高水位损坏、断电、MCU部分成功、全部入口一致。
8. 存储：factory/data 哈希/内容按保留契约核对；整写流程显式区分；新旧布局分别实测，不能用 Host 替代。
9. 制品：生产 profile、US、语言、云环境、源码/镜像/签名身份一致；所有发布路径拒绝缺失身份和混入调试资产。

缺少真实设备、签名材料或 owner 契约时可完成 Host/接口候选，不得将产品项标 PASS。正常业务的失败恢复与安全拒绝范围分别定义，不因非关键资源失败终止主进程。
