有效区域配置唯一来源为/factory/app_config.ini，保留原通用项，新增AREA/WIFI和云侧所需项。AREA.area_code和WIFI.ccode均US并相同；app_id和各endpoint节名/类型/长度及组合需云/IoT一次冻结。不新增area_version。

启动：挂载factory -> 校验完整INI及支持区域 -> 核US无线启动默认并在联网前确认实际值 -> 加载用户设置/基础资源 -> 启动相关业务。动态读回所用接口须板端确定；静态US文件不代替实际验证。

产线写入：确认挂载/空间/权限 -> 校验候选完整INI -> 同目录临时文件同步 -> 原子替换并同步父目录 -> 回读 -> 重启应用实际验证。单writer串行操作，不能覆盖其他身份/校准文件。配置损坏由既有工装入口修复，云和常开shell不能成为必需前置。

首发固定配置合同，例如config_contract=1仅放发布manifest和固件编译合同中，不作INI区域版本。升级时验证目标支持当前有效配置；不兼容直接拒绝，不做自动迁移。普通恢复出厂删除账户/网络/用户偏好，保留区域、身份、校准；工装改写是另一个明确操作。

## 6. 时区完整闭环

### 6.1 扫码配网

新增片段：{"timezone_id":"America/New_York"}。保留原配网payload结构，最终字段名及编码由APP/二维码解析owner确认；字段可缺省以自然进入网络补全，不建立新旧协议迁移框架。

APP读取手机系统时区ID，不要求GPS。只传IANA地区ID或已明确支持的别名；不使用US/EST/UTC偏移替代地区规则。设备先校验字符串长度（建议上限64字节）、允许形式、路径不越界和本机zoneinfo可读有效，不能拼shell。支持别名以随包zoneinfo实际表为准，不自行维护大映射库。

提交时机：二维码解析后先暂存候选；既有配网/绑定的配置提交成功后，才由唯一writer合入timezone_id和timezone_source=app。配网失败/绑定拒绝不覆盖旧设置。时区缺省或非法只报告该字段问题，不撤销已成功的Wi-Fi/绑定；已有合法时区保留，无合法值则联网补全。二维码及日志不能输出Wi-Fi密码、token或完整payload。

建议配网反馈只补充：timezone_id、source、saved、applied、timezone_error；保存成功但运行应用失败必须如实区别。手机设置错误无法自动识别，APP结果页可展示当前同步时区并允许明确重同步；远程打开APP不自动覆盖设备。

### 6.2 网络自动补全

通过现有IoT/云接口返回IANA时区，例如{"timezone_id":"America/Los_Angeles","source":"device_setting"}，或明确unknown。云侧优先使用已登记安装地；无该值时可按设备请求出口IP估计，source标为ip。该接口是本方案建议，当前存在性/具体字段尚未验证。

只在没有合法当前时区时启动补全；网络请求发起与响应落地均检查当前用户/设备绑定及当前时区来源。期间已有扫码值、解绑/恢复出厂或绑定变化，则丢弃旧响应；复用现有请求上下文和同一writer串行检查，不建立独立仲裁框架。network值也是候选，不改区域和云归属。

请求在首次联网/后续网络恢复且缺值时触发；建议超时5秒、失败后隔60秒重试，每轮最多3次，之后等下一网络恢复或明确同步动作，不忙轮询。参数可复用现有网络退避。结果unknown/非法不保存为有效值；禁止关闭TLS证书校验来解决初始时间错误。

已有合法app/network值则继续使用，IP推断不自动覆盖。搬迁或错误值由重新扫码/明确设置纠正；首发不做无人值守跨时区搬迁检测。设备断网仍使用已保存时区及规则，夏令时转换不依赖在线查偏移。

### 6.3 时间与生效

clock_ready与timezone_valid分开：前者由现有RTC/NTP时钟服务判断UTC可信，后者表示合法ID和规则已加载。日历类任务在二者满足后执行；缺值时明确不可用，不影响手动控制或安全回充。RTC掉电/时间明显错误先按既有校时流程恢复，不假造ready。

建议zoneinfo随customer放/customer/share/zoneinfo，便于随固件更新，不建设tzdata热更。覆盖CN和全部实际销售的US时区及必要别名，按目标glibc验证；/etc/localtime在新出厂rootfs固定链接到/data/system/localtime，由System从已保存ID生成派生链接，最终指向受限zoneinfo目录。该链接是运行派生物，不是第二份权威用户配置。实际目标镜像若已有可靠等价机制可复用，但必须保持一份有效ID。

进程启动由统一设置生成TZ/调用tzset；运行更新时System和Task等相关消费者显式刷新。对可能并发的本地时间转换，采用现有时间服务串行更新/重算，不在任意线程反复改进程全局TZ。只读路径不写shell；失败返回明确错误；启动从持久ID重建派生链接。保存失败继续旧值；已保存但应用失败显示saved=true/applied=false，保持日历任务未就绪，重试或重启按既有流程恢复。

GNU libc对不可读/无效TZ文件可能静默使用UTC，所以不能只靠tzset返回就认定成功；应用前校验规则文件，应用后按测试时刻检查转换，目标板验证重启及多进程一致性。

### 6.4 DST与Task

系统时间使用UTC。单次超时/间隔用现有单调时间机制，休眠是否计入按原业务核对，不擅改90分钟寻宠间隔。

日历槽位：春季不存在的槽位本次跳过；秋季同规则同本地日期同计划槽位只执行一次；不同槽位/不同规则不合并；校时或换时区后重算下一次，不突然补执行过去的危险动作。去重状态跟随现有Task规则状态持久化，明确重启不会重复；规则编辑按新规则处理。此为建议冻结语义，需要Task/product确认，不以新建调度器实现。

间隔寻宠与上述日历去重分开，保持已有工作窗口、首次条件、90分钟重试和安全条件。任何时间改动都不能把“每天一次”施加到整个寻宠功能。

## 7. 最小可信OTA：不改变原包内部格式

### 7.1 三个发布文件

- 原包：既有ota_pkg_<version>.tar.gz（整机），或SStarOta.bin.gz（SOC-only）。原内部guide、载荷、脚本结构不改。
- ota_manifest.json：固定UTF-8编码，包含kind=vehicle_ota/soc_ota、product、board、layout、channel=production、supported_regions、配置合同、selected_components及组件目标版本、payload_filename、payload_size、payload_sha256。生产入口强制channel匹配，不能只依赖下载目录区分调试包。
- ota_manifest.sig：对manifest原始精确字节的独立签名。验证端不重序列化后验签；JSON重复键、缺必需字段、未知kind及超限清单拒绝。

manifest内选中组件与实际包/guide严格一致，不允许签了一个版本却执行另一个guide。整个包的SHA256已覆盖内部脚本和载荷，无须再增加每文件签名或重复一套包内升级协议。SHA256 sidecar/MD5/CRC可留诊断和既有格式用途，不承担身份认证。

签名使用现有成熟密码库。建议默认RSA-PSS/SHA-256（2048位，MGF1-SHA256，salt长度32字节），单一预置发布公钥；若发布端已有标准算法，实施前双方一次冻结等价合同，不能运行时由不可信manifest任意选择算法。设备用目标库EVP等标准接口，发布侧可用官方工具；不自研密码算法或新增通用签名框架。公钥随固件内受控材料发布，私钥不进设备/仓库；本轮不生成密钥。

### 7.2 设备顺序与版本

有界读manifest和signature -> 用固定公钥验证 -> 核产品/板级/区域/布局/配置合同及大小限制 -> 下载/取得完整原包并验证其大小与SHA256 -> 安全解包到专用目录 -> 检查guide/组件/脚本集合与manifest一致 -> 进入现有停业务及写入。

下载前可先校验manifest避免浪费空间；包校验完成前不得执行任何包内脚本，包括before_update。整包验证后禁止其他writer替换；执行仅使用本次验证后的同一包/隔离目录。拒绝穿越路径、绝对路径、越界链接、额外可执行项和超限解包。

各选中组件按自身已冻结版本语法查询当前/目标，不直接比较字符串，不用区域tag参与数值比较。普通包禁止任何选中组件降级，至少有一项升级；其余选中组件可同版本。全部同版本时仅同一已验证包的重复请求按既有真实记录处理；相同版本不同内容拒绝。当前版本未知则拒绝对应升级，不猜测0。对同包此前写入失败，是否重试由现有执行器判断，不能因临时文件存在直接报成功。未选择的组件不参与更新，不强求SoC版本提升才允许合法MCU更新。

保存当前version.ini及现有结果即可；不增加闪存高水位/硬件防回滚。此保证普通软件升级策略，不声称抵御物理重刷。

### 7.3 交接、失败和保数据

验证在现有OTA入口完成，之后沿用prog_ota到/tmp执行器的交接。交接前确认包、脚本和依赖在customer卸载后可用；校验结果绑定包hash。实际执行、错误码和结果记录由现有执行器负责，不能依赖被杀掉的customer进程。不新增产品状态机。

普通OTA不得携带factory/data/整写ubia；保留账户、区域、校准和资源。空间不足/包不适用在停业务前拒绝，写入失败按真实结果返回。SoC/MCU/轮电机的顺序与部分失败恢复复用现有合同，但必须用该候选包实测；不承诺整机事务回滚。

所有当前对用户开放的正常入口都先过同一验证：整机、SOC-only及若启用的SD/本地更新。未接入验签的入口在生产禁用，不能留下绕过；不设计历史未验签版本的过渡链。写入流程成功就是升级成功，重启后检查属于发布HIL，不加PENDING_BOOT。

## 8. 中英文资源及热更新

### 8.1 位置与最小离线集合

customer：程序/库、基础资源、zoneinfo、验签公钥、必要离线英文提示。data：用户设置、可更新资源包和激活记录。factory：区域/身份/校准。保持当前分区布局。

按逻辑用途划分locale/en-US、locale/zh-CN、common；动物声/白噪音等通用内容只存一份。AI/KWS、导航参数、校准、证书不放入普通声音更新。本轮只更新真正需要独立发布的声音/内容，图片等若不需要热更继续随固件。

内容owner冻结关键ID清单：首次启动、配网指引、连接结果/失败、低电或必要故障、恢复出厂等按产品实际需求列明。US出厂断网时英文关键ID必须在customer可用；可选娱乐资源缺失只使对应功能不可用。不静默播放其他语言：目标语言包不全时明确反馈未可用，必要提示采用事先确认的基础语言规则。语言选择不改时区/国家/云。

### 8.2 包、解析和激活

资源包延用同一sidecar验签思路，kind=resource，额外给出resource_contract、语言/内容类型、资源版本。固件编译一个固定resource_contract；安装和开机/固件升级后均检查，不兼容时忽略活动包并用基础资源，不自动迁移。

只做一个资源读取入口：逻辑ID按当前有效包清单解析，缺少时仅走清单明确允许的基础资源。避免任意按data文件存在覆盖customer。首发包使用完整所选语言/内容集合，不做增量差分或复杂依赖图。

更新：下载到data专用staging -> 验签/整包hash/兼容/清单及解包上限检查 -> 安全解包到新的完整版本目录 -> 同步文件和目录 -> 原子切换活动清单 -> 新播放使用新版本。活动记录单writer，当前播放持有版本直到结束；资源GC只删除非活动且未被消费的旧包，上一有效包保留。可采用消费者计数或安全生命周期回收，选现有机制，不建立通用对象库。

签名有效也只能写资源命名空间；拒绝脚本、可执行文件、特殊节点、越界路径及链接，不触碰用户配置/证书/校准。启动发现活动记录损坏或新固件不兼容时，选择仍兼容的上一包，否则基础资源；下载/断电/满盘失败不毁当前资源。

容量按当前+上一包+压缩下载+候选解包+业务数据/日志余量核验实际峰值；空间不足拒绝更新。资源包版本独立于固件版本，但必须满足固定合同；本地退回已验兼容上一包允许，不混用固件降级策略。

### 8.3 仓库

ota_f10组装固件与整机包；app_ssc305保存应用发布输入及必要基础资源；独立resources_ssc305目录或仓库管理需独立发布资源、manifest与构建。可用现有制品存储放大文件，Git存清单与来源；不创建整个data运行态镜像仓。

修改Sensor/Task受影响的资源入口，不使用整棵customer OverlayFS，不增加无必要挂载兼容层。源码、应用发布输入、customer镜像、SoC包和整机包逐级重生，后编译不会更新已有包。

## 9. 生产调试与镜像

生产禁用SSH/ADB/Telnet、串口shell、应用危险命令及普通SD开关；检查Bootloader实际可用的交互入口按产品生产策略关闭。串口日志与交互分开，MCU业务UART保持。

不开发远程shell授权平台；使用既有制造/售后工装和受限诊断。具体工装需保证可修复无效区域配置而不依赖云或常开shell。若当前没有该入口，交付一个针对本需求的最小工装操作，不能用“以后确认”绕过验收。

rootfs入口修复必须进入实际新出厂rootfs；当前OTA构建不支持rootfs不妨碍制造使用新系统基线，但不能宣称customer OTA修复了rootfs。后续正常维护若需要更新rootfs需独立明确范围，本轮不增加历史迁移链。生产/调试制品分明，生产验签策略拒绝调试渠道包。

AP脚本与hostapd.conf的移除按已确认二维码配网实际通道验证：扫码配网不能依赖被移除脚本。旧data文件清理失败仅告警，不能阻塞主程序。只把与当前需求有关的系统变更纳入首发，不新增平台升级。

## 12. 执行顺序和范围控制
