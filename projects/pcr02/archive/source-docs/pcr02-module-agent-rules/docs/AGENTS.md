# 项目 Docs Agent 规则

## 1. 基本信息

- 子目录：`docs`
- 角色定位：当前项目强绑定文档入口
- 团队知识库：`~/embedded/knowledge`

## 2. 职责范围

- 维护当前项目架构、项目构建部署、项目设计规格、实施计划与验证报告。
- 维护当前项目工具说明，但公共工具实现应保留在 `~/embedded/knowledge`。
- 记录与本仓源码、构建脚本、产物路径强绑定的事实。
- 引用团队通用规范、排障手册和公共工具时，优先指向 `$EMBEDDED_KNOWLEDGE_HOME`。

## 3. 依赖边界

- 项目特有内容保留在当前 `docs/`。
- 项目工具适配层保留在当前 `tools/`，仅承载 wrapper、README 和项目默认参数。
- 跨项目复用内容沉淀到 `~/embedded/knowledge`。
- 不在当前项目仓重复维护通用文档治理脚本、模板、公共调试工具和团队 skill。
- `plans/` 与 `reports/` 默认按历史资料维护；只有明确仍作为当前执行入口时才允许 `status: active`。

## 4. 禁止事项

- 禁止把团队通用知识重新复制回当前项目仓。
- 禁止把项目阶段性结论写成团队通用规范。
- 禁止在未校验源码、构建脚本或实际产物前写“已支持/已完成/已上线”。

## 5. 规范要求

- 项目文档必须明确目标、范围、验证依据和适用版本。
- 通用编码规范、排障流程和工具说明以 `~/embedded/knowledge` 为准。
- 当前项目文档中若引用知识库内容，使用 `$EMBEDDED_KNOWLEDGE_HOME/<path>` 或远程仓库路径描述。
- 历史计划和报告应使用 `status: archived`，避免未完成步骤、旧门禁命令或阶段性结论被误当成当前规则。
- 若需要重新启用历史计划，必须先创建新的执行计划或更新状态，并重新核对源码、构建脚本和验证命令。

## 6. 最小验证

- 构建相关文档：核对 `Makefile`、`build/*.mk`、对应 `dep.mk`。
- 模块相关文档：核对 `modules/`、`include/`、`pcr02/`。
- 知识库引用：核对 `~/embedded/knowledge` 是否存在对应文档或工具。
- 历史记录中的旧脚本路径只作为审计信息；当前门禁必须以本仓实际存在的脚本或知识库当前入口为准。

## 7. 推荐入口

- 项目文档入口：`docs/README.md`
- 项目工具入口：`tools/README.md`
- 团队知识库入口：`~/embedded/knowledge/README.md`
