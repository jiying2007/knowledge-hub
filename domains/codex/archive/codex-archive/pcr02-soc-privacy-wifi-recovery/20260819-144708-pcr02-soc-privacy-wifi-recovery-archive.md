# PCR02 隐私休眠 Wi-Fi 恢复与 TCPKA 回退

## 背景

设备在隐私休眠期间遇到 Wi-Fi 去关联或接入点不可用时，不能因为异常唤醒、后台关联或低功耗门禁失败而恢复业务和 LCD 背光。

## 决策与实现

- 将 `Disassoc/Deauth` 等异常 Wi-Fi 唤醒保留在隐私休眠内部处理：业务和背光不恢复。
- 每次内部唤醒先给已保存凭据有限恢复窗口；仅在实际链路已连接时重臂 TCPKA。
- 无法重臂 TCPKA 时配置短 RTC 重试，避免永久失去恢复机会。
- 低功耗恢复使用独立于普通配网的更短连接 API 超时，防止底层连接调用超过恢复窗口。
- 恢复窗口超时后，显式关闭自动重连、停止扫描并请求断开 Wi-Fi；然后再执行 RTC 回退和 suspend gate，避免驱动迟到关联使低功耗事务回滚并点亮屏幕。
- suspend gate 只在 Wi-Fi 扫描、连接 API 和状态变化稳定后允许 MCU arm；失败必须清理 RTC/TCPKA/传感器状态。

## 诊断要点

- `wakeind=0x4` 表示去关联/去认证异常唤醒，应进入内部重试。
- `wakeind=0x2` 表示网络模式匹配，是正常 TCPKA 远程唤醒，不应与 RTC 重试混淆。
- 连接 API 返回失败不等于底层 Wi-Fi 状态机已停止；若随后出现迟到的 connected 事件，优先检查自动重连与未取消的关联过程。
- `SOC low power rejected because WiFi is busy before suspend` 表示事务安全回滚，而不是一次有效的业务唤醒；背光恢复是回滚后果。

## 验证与风险

- 受影响 Wi-Fi 和低功耗源文件已做交叉编译语法检查；独立 sensor 仓库空白检查通过。
- 协同低功耗静态检查在现有 DHD 内核基线缺失项上失败，未作为 sensor 逻辑通过证据。
- 需要设备侧回归：连续断开/恢复 AP，确认失败路径持续关闭背光并进入 RTC 重试，恢复链路后能再次重臂 TCPKA。
