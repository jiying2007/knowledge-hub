# Knowledge Provider 全归属检索与归档实施方案

## 结论与适用范围

项目身份独立于 Git。Git remote、commit、目录位置只提供来源和定位证据，不决定用户主体或归档授权。首期支持 project、domain、personal、unassigned 四类主体；domain 自动候选仅允许 embedded 与 codex。所有自动归档保持 reviewing、promotion=none。

本方案替代先前仅依赖仓库远端的路由设计。旧方案记录保留为历史审查候选；本记录仍是 reviewing，不能作为团队已发布规范或 owner 决定。

## 三种主体分别表达

- execution_subject 表达当前任务明确归属。
- retrieval_scope 表达本次允许查询的项目、领域或本人资料范围。
- archive_subject 表达候选的目标归属，单独接受策略和授权校验。

查询词仅参与 discovery 和排序，不创建项目、不建立绑定、不赋予写权限。跨项目检索不会改变当前归属。显式项目或 logical workspace 与当前已绑定项目冲突时，归档预检不可用；跨项目写入需精确授权。

## 工作目录与项目登记

明确项目通过真实用户声明登记 logical workspace。register/bind 的 grant 必须绑定实际当前线程、当日 intake、真实用户消息、声明 SHA 和预期操作 hash。Git 作者、聊天中推测的人名、目录 basename 和 README 都不能代替声明。

项目登记建立知识入口、canonical route 和 knowledge-project evidence profile；普通目录不建立伪造 repo。source、owner、validation 分层保持 pending，目录存在不代表源码已核验。

本机显式 bindings 与自动 discovery 分开存储。绑定保存 canonical/requested path、目录 device/inode、coverage、generation 与授权引用；采用最长路径匹配和组件边界匹配。目录替换或 symlink 改向成为 stale。独立子仓、remote 与绑定冲突时拒绝继承父项目。

linked worktree 从自己的 gitdir 读取 HEAD，从 common directory 读取 remote 与 refs；无 Git 的来源记录 vcs=none、commit=null。未建立提交的本地 Git 可以 commit=null，verification_state 仍为 unverified。

## 四类候选

project 使用已登记 canonical route。领域提炼进入 allowlisted domain 的候选空间，需显式 team-general 声明。个人草稿和未明确归属资料分别进入本人 personal/unassigned 范围，不能成为团队 active 事实。

personal-local 限制 Provider 默认检索和团队导出；脱敏正文进入 Git，因此它不是对仓库读取者的隐私隔离，也不清除 Git 历史。不得存放 raw session/log/core/binary、secret、客户或设备标识。

## 归档、重试与重新归属

归档策略同时校验 schema、candidate-only mode、严格 enabled boolean、allowlisted kind、注册 owner、字节预算和脱敏输入；提交准备阶段重新核验。操作回执与 context eligibility 使用一致策略。

item_id 与 operation_id 稳定。正文、registry、索引、lifecycle 与 operation ledger 在同一可恢复事务中写入；读回核验最终正文 hash 后才返回 persisted=true。个人与未分配候选不宣称 project_archived。

超时或提交后读回异常返回 UNKNOWN 并保留 operation_id；先 reconcile，不盲目重写。只有 ARCHIVED、ALREADY_ARCHIVED 等明确成功语义与 persisted=true 才可宣称记录完成。

assign 保留 item_id，精确绑定目标主体、旧正文 hash、可见性变化、执行主体与 reviewed authorization；搬移正文和索引同事务，单正文维护。操作索引更新 current_subject/current_content_hash，使历史创建重试指向实际现归属。迁移不赋予 owner approval 或 active promotion。

legacy v1 导入仅观察现存身份和 hash，不声称历史 validation_verified。旧 payload 以 v2 重试时复用已导入 stable item，避免 API 切换产生重复正文。

## 检索、缓存和协议

context v3 独立表达 execution、retrieval 和 archive eligibility；保留旧 context v2、archive v1。未知版本或不适用的非默认参数拒绝，不能静默忽略写目标。

默认团队检索排除 personal-local。本人资料需显式 personal/unassigned scope 和已配置 principal。结果区分 authoritative、provisional、historical、discovery；reviewing 不升级为 active。

v3 缓存绑定协议、完整参数、query hash、registry/policy/grants/bindings/principal、目录解析状态、日期和所选正文 hash。缓存不保存原 query；路径必须在 Hub 内。small summary 优先保留主体、冲突和权限信息，缩减结果行。

capture-source 仅对显式相对文件 allowlist 生成 size/hash manifest，限制数量、单文件、总字节和运行时间，拒绝 symlink、secret、raw log、会话和二进制。manifest 表达 observed/partial/unstable，不等于已验证源码。

## 公开调用示例

跨仓只使用 Provider adapter；内部实现目录不作为跨仓契约。

```bash
rtk bash ~/codex/scripts/knowledge-provider.sh status
rtk bash ~/codex/scripts/knowledge-provider.sh resolve --cwd "$PWD"
rtk bash ~/codex/scripts/knowledge-provider.sh context --api-version 3 --cwd "$PWD" --query "任务主题" --summary-json
rtk bash ~/codex/scripts/knowledge-provider.sh context --api-version 3 --workspace workspace://a123x --query "任务主题" --summary-json
rtk bash ~/codex/scripts/knowledge-provider.sh archive --api-version 2 --cwd "$PWD" --subject project:a123x --source /tmp/sanitized-conclusion.md --kind audit --sanitized --dry-run
rtk bash ~/codex/scripts/knowledge-provider.sh archive --api-version 2 --cwd "$PWD" --subject project:a123x --source /tmp/sanitized-conclusion.md --kind audit --sanitized --apply
rtk bash ~/codex/scripts/knowledge-provider.sh reconcile --operation-id <operation_sha256> --expected-content-sha256 <content_sha256>
```

未明确项目时显式选择 unassigned:<configured-principal>；跨领域或个人范围查询使用 v3 的 retrieval-domain、personal、unassigned 参数。register/bind/assign 先 dry-run 获得预期 hash，再经适用 grant/授权流程执行。

## 实施与验收边界

A123X 已实际完成项目登记和本机绑定，v2/v3 查询均解析到 project:a123x；本地 Git 缺远端和提交不会阻断知识身份。普通无 Git 目录与四类候选通过隔离 fixture 验证。

最终验收分别要求定向测试、Hub 全量回归、Runtime 请求核验、真实 Provider archive/reconcile、独立最终差异复审和 Execution Policy final gate。源码测试、Provider operation、运行资产部署、owner/active 与产品资格分别报告。

本方案不授权 commit/push/merge、源项目修改、memory 写入、团队 active 提升或外部发布。现有脏改保持；Runtime 本机配置另走受管 source-to-live 流程，不能顺带部署与本任务无关的配置变化。
